## ① 宅邸篇场景细分现状：**被动事件驱动，无主动场景选择**

### 现状
- **场景推导**：`shared/vignette.py::_derive_location`（L505-529）从 `active_event` 关键词启发式推导地点——仅覆盖走廊/花园/书库/庭院/后院/大厅/窗边/向阳处 8 种
- **事件池**：`EVENT_POOL`（state.py L111-120）8 条，地点集中在走廊/花园/庭院/后院/书库/窗边
- **动作池**：actions/*.json 场景词：走廊/大厅/窗边/庭院/门厅/书库/木柜/餐桌
- **LLM 模式**：场景信息经 `to_prompt_text`（「当前事件：…」）注入 system prompt，LLM 自由发挥场景描写

### 缺口（用户提出的细分场景均无）
| 场景 | 现状 | 缺口 |
|---|---|---|
| 庭院/花园 | ✅ 有（garden_bloom/cat_visitor 事件） | 无独立场景对话库 |
| 一楼/大厅/餐厅 | 🟡 大厅有，餐厅无 | 无餐厅场景（用餐互动） |
| 二楼/卧室/客房 | ❌ 无 | 无卧室场景（晚安/深夜谈心） |
| 厨房 | ❌ 无 | 无厨房场景（做饭/烘焙/偷吃） |
| 走廊 | ✅ 有（tea_ready/cleaning） | 场景较单一（只能路过） |
| 书房/书库 | 🟡 书库有 | 无书房阅读场景 |
| 浴室/洗衣房/仓库/阁楼 | ❌ 无 | 全缺 |

### 结论
**场景是「事件随机掉落的被动结果」，用户无法主动选择场景**；且 `active_event` 会话中途不刷新（README 已知遗留），一次会话内场景固定。这是「场景化体验」最大的结构性缺口。

## ② 事件触发后用户询问的回应机制：**依赖 LLM 自由发挥，无结构化回应指引**

### 现状
- 事件经 `to_prompt_text` → 「当前事件：{desc}」注入 system prompt
- 用户问「今天宅邸有什么新鲜事？」→ LLM 基于注入的事件描述生成回复
- **无**事件→角色回应（蕾姆/拉姆对该事件的专属台词倾向）的结构化映射
- **无**「事件记忆」：事件不写入 events（长期记忆），跨会话无法回忆「上次那件事」

### 缺口
1. 事件只有描述文本，没有「蕾姆视角/拉姆视角如何回应」的引导（如野猫事件→蕾姆想收养/拉姆嫌麻烦）
2. 事件不落长期记忆 → 用户隔天问「昨天那只猫呢？」LLM 答不上
3. 事件无互动深度（不能发展成小剧情，只是背景板）

## ③ 天气 × 事件冲突：**确认存在，且是概率性必然**

### 现状（实锤）
- `_pick_active_event`（state.py L203-214）：仅用 `(日期, 时段, 天气, 种子)` 做 MD5 选事件，**无天气兼容过滤**
- EVENT_POOL 事件**无 `weathers`/`periods` 字段**（与 registry.json 的模板条目不同——后者有 weathers 过滤）
- 冲突实例：`cat_visitor`「野猫从庭院围墙跳进来，正晒着太阳」在大雨天被选中概率与其他事件相同 → **大雨天野猫晒太阳的冲突必然概率性出现**

### 严重度
- 用户可见（引言/事件注入 prompt 会描写「晒着太阳的野猫」+「雨水敲打窗户」同屏）
- LLM 可能察觉矛盾（「雨这么大，猫怎么晒太阳？」）或无视（各写各的，出戏）

## ④ 中文排版：**基础可用，但无中文排版优化**

### 现状
- 气泡正文 11px（FONT_SIZE body_lg）、辅助 8-9px——**验收报告 P1 遗留（字号偏小，长文阅读疲劳）**
- `QLabel.setWordWrap(True)`——换行交给 Qt 引擎，**无避头尾（行首禁则）/标点悬挂处理**
- 无行距定制（QLabel 默认单倍行距）
- 气泡内 padding 12px 16px，气泡宽度受窗口约束

### 缺口（中文阅读习惯）
1. **行首禁则**：中文标点（，。！？）不应出现在行首——Qt 默认对 CJK 有一定处理，但无显式保证
2. **标点悬挂**：行尾标点可悬挂以对齐右侧
3. **行长控制**：LLM 长回复每行 40+ 字在窄气泡内挤压，无「每行 ≤30 字」的中文阅读最优行长
4. **段落间距**：多段台词之间无视觉间距（只有换行）

## ⑥ LLM 对齐原著特色的机制建议（不改，仅建议）

### 现状
- prompt 唯一 Re0 专有词：「魔女残香」（_build_special_states）
- 原著贴合 100% 依赖 base model 对 Re0 的先验知识——**无显式锚定，输出质量不可控**

### 建议机制（分层锚定）
1. **角色卡（Character Sheet）注入**：prompt 加「原著设定锚点」小节——蕾姆（身份：罗兹瓦尔宅女仆/鬼族/爱蜜莉雅阵营；性格：自卑→救赎、忠诚、家务全能、茶艺、对姐姐的复杂情感；口头禅/说话方式样本）；拉姆（毒舌护妹、托付语义、对罗兹瓦尔的忠诚）
2. **Re0 专有词汇表**：巴鲁斯（昴）、罗兹瓦尔宅、贝蒂、魔女残香、圣域、龙历石、鬼族——prompt 注入「可自然使用的世界观词汇」，限定不越界（不扮演昴/不改变剧情）
3. **场景化人物反应库**：关键人物出场时的蕾姆/拉姆反应倾向（如贝蒂→蕾姆日常互动/拉姆拌嘴）
4. **名场面状态联动**：鬼化/失忆/重逢触发时，注入对应原著场景语感（比 SCENE_GUIDES 更重，如「从零开始」是蕾姆灵魂台词）
5. **LLM 生成校验增强**：validator 增加「原著一致性」软检查（出现 OOC 词汇/违背人设的表达）

### 为什么这样能让 LLM 更有韵味
- 当前 LLM 输出的「蕾姆味」来自 base model 对 Re0 的记忆——**不稳定**
- 显式锚点 = 把「蕾姆应该怎么说话」从模糊先验变成确定性约束 → 每次生成都有原著基底
- 结合已完成的 SCENE_GUIDES（12 场景）+ 事件语义召回 → 场景×人物×记忆三层叠加，沉浸感自然提升
