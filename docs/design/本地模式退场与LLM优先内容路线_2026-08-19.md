# 本地模式退场研判 + LLM 优先内容密度新路线

> 日期：2026-08-19 ｜ 依据：用户方向决策「本地模式过于模板化，最初仅作为 LLM 模式的地基，准备适时放弃」+ 内容密度研判（2026-08-19）+ Trial #1-3 实测数据
> 一句话结论：**local 模式的历史使命（验证状态机架构、提供零 API 开发地基）已完成，LLM 模式已证明产品级（角色 9.5/10）——本地模式应从「产品功能」降级为「开发/测试地基」，分三阶段退场，腾出的内容投入全部转向 LLM 内容资产。**

---

## 0. 为什么退场是对的（Trial 数据背书）

| 维度 | local 模板模式 | LLM 模式 |
|---|---|---|
| 角色吸引力 | 复读机修复后仍模板化（A-02） | **9.5/10**（Trial #1 Phase 4） |
| 情感层次 | 有限（词库池） | 完整弧线（Trial #2-A 32 轮） |
| 边界处理 | 三级模板（A-01 修复） | 颤抖+护妹立体反应 |
| 跨天记忆 | 无（词库不记忆） | 细节记忆（七十五度茶） |
| 帝国篇语感 | 模板分桶 | recovery 梯度天然成立 |
| 维护成本 | 23 桶 × 3 arc × 5 档文案 = **345 条文案要维护** | 内容资产（vignette/letters/prompt）可复用 |

**结论**：local 模式的分母（345 条文案 + 引擎桥接 + 双模式测试）越来越大，分子（用户价值）越来越小。LLM 模式已不需要它当「成品」，只需要它当「地基」。

## 1. 影响面盘点（退场要动什么）

### 1.1 本地模式代码资产

| 模块 | 现状 | 退场处置 |
|---|---|---|
| `local/rem_ai.py`（RemAI） | 本地蕾姆模板引擎 | **保留为测试地基**（L0 零 API 冒烟用） |
| `shared/prompts.py::ResponseLibrary`（345 条文案） | 本地词库 | **停止扩池**（S-01/E-02 已修不再加新文案） |
| `shared/prompts.py::RamAI` | 本地拉姆模板 | 同上，停止扩池 |
| `local/twin_system.py`（ReZeroTwinSystem） | 双子总控 | 保留（测试/降级） |
| `main.py --mode local` | CLI 入口 | 保留（开发调试用），但非默认卖点 |
| `gui.py /local` 切换 | GUI 模式切换 | **降级为开发开关**（不再面向用户宣传） |

### 1.2 内容资产现状（内容密度研判 Step 0-4 已落地）

```
content/templates/registry.json  69 条  （vignette/proactive/return_flavor，三 arc）
content/letters.json             43 条  （来信，三 arc 分桶）
content/actions/{rem,ram,twin}   60 条  （动作池，纯宅邸）
content/openings/mansion.json    6 条   （短开场）
```

**缺口（LLM 优先视角重新排序）**：
- 帝国篇 proactive（来信）仅 3 条——离线回归帝国场景易重复
- 后期篇 vignette 7 条 / proactive 6 条——薄

- **没有「场景库」**：Trial #2-A 证明 LLM 情感弧线优秀，但内容密度研究报告的 §5 矩阵（篇章×slot）只做了 vignette/letters，**缺「LLM 模式专属内容」：场景提示（SCENE_GUIDES）、剧情节点（arc beat）、事件→prompt 注入**——这才是 LLM 优先的内容投入点

## 2. 退场路径（三阶段，每步可验收）

### Phase A：冻结（立即，零风险）
- **停止 local 文案扩池**：ResponseLibrary/RamAI 不再加新档位/新文案（S-01 已修的池保持现状）
- **README/文档降权**：local 从「零 API 可玩」卖点改为「开发调试模式」
- **验收**：CHANGELOG 记录冻结决策；文档不再宣传 local

### Phase B：降级（近期）
- GUI `/local` 切换改为开发者可见（加「开发模式」标注，状态栏提示）
- local 模式保留为 **L0 零 API 测试地基**（smoke_test/test_favor_growth 依赖它，不动）
- **内容投入重定向**：原先准备给 local 扩池的精力 → 转到 LLM 内容资产（见 §3）
- **验收**：pytest 仍 107/107；用户路径（默认 LLM）体验不变

### Phase C：可选移除（远期，用户确认后才做）
- 若 local 的测试地基价值也被替代（如引入 mock LLM 测试框架），可整体移除 `local/` 与 ResponseLibrary
- **前置条件**：LLM 模式测试全部改为 mock（test_llm_failures 已有雏形）
- **验收**：移除后 pytest 全绿（测试改用 mock LLM）

## 3. LLM 优先的内容密度新路线（V14.5+）

> 内容密度研判报告 §4-5 的注册表/篇章矩阵方向不变，但**投入重心从「模板文案池」转向「LLM 内容资产」**：

### 3.1 优先级重排

| 优先级 | 内容资产 | 现状 | 行动 |
|---|---|---|---|
| **P0** | **SCENE_GUIDES 场景库扩充** | 仅 4 个（breaker_promise/identity_affirm/hug_accept/headpat_comfort） | 扩到 12+：离别的重量/重逢的试探/战后的疲惫/深夜的倾诉/愿望/道歉/守护的誓言/日常的闪光 |
| **P0** | **事件→prompt 注入增强** | events 6 条注入 | 事件记忆语义召回（README 遗留项）——LLM 模式高价值 |
| **P1** | 后期篇 proactive 扩池 | 6 条 | 扩到 10-12 条（战友语感） |
| **P1** | 帝国 proactive（离线×recovery 档） | 16 条（Hermes Step 3 已扩） | **已达标，冻结** |
| **P2** | 动作池（actions/*.json） | 60 条宅邸 | **不再扩**（LLM 生成，L2 模板兜底够用）——冻结 |
| **P2** | 开场引言（openings/*.json） | 6 条 | 冻结（registry vignette 已接管） |

### 3.2 新增：LLM 专属内容形态

1. **剧情节点（arc beats）**：核心剧情（从零开始/失忆/托付）的**场景级提示库**——像 SCENE_GUIDES 但按 arc×recovery 分桶，让 LLM 在关键节点自动获得「此场景该有的情感重量」（Trial #2-C 证明 recovery 梯度天然成立，用 beats 给它导航）
2. **事件语义召回**（README 遗留）：事件记忆按语义召回而非 6 条硬注入——LLM 模式价值最高
3. **来信场景化**：letters.json 已有 arc 分桶，补「场景触发」维度（下雨天/节日/战斗后），让主动来信更「因为所以」

### 3.3 明确不做（延续研判报告的克制原则）

- 不把 LLM 模式改成「查表生成」（内容资产是提示不是答案）
- 不为 local 模式再做任何体验追平（A-02 从「修复目标」改为「已知差异，接受」）
- 不复制一套 LLM 内容给 local（退场方向相反）
