# V15.0「年轮」版本构思——关系资产（Relationship Assets）

**日期**: 2026-08-29
**状态**: 构思稿（待用户确认后排期）
**产品定位（本轮确立）**: 一个会陪你一起变老的数字关系。
**版本主题句**: 模型决定她今天会说什么，时间决定她是谁。

---

## 一、为什么是这一版（背景与动机）

产品定位从「AI 桌宠 / Galgame AI / 桌面陪伴」收敛为「数字关系」后，架构优先级重排：

```
Relationship（关系资产）
├── 时间(Time)          ← 现在：WorldState 分散字段，无显式资产
├── 共同经历(History)    ← 现在：conversations.db + engine.events(30条上限!)
├── 世界(World)          ← 已完备：时段/天气/事件/场景/篇章
├── 长记忆(Memory)       ← 已完备：结构化画像 + 事件语义召回
└── 表达(LLM)           ← 最后：只负责"她怎么讲"，不负责"发生过什么"
```

诊断：**关系的原料全部已在系统里，但没有任何一处把它们当作"资产"对待**——

- `engine.events` 是工作记忆（30 条环形 + 钉住），不是人生记录；
- `conversations.db` 是对话流水，不是被组织过的共同经历；
- 相识了多少天、一起过过几个春节、第几封信——**这些事实系统算得出来，却从未被计算和呈现**；
- 全部资产散落在 5 个文件里，重装即散失——"时间不能丢"目前只是愿景，没有工程保证。

V15.0 要做的就一件事：**把隐式的关系沉淀，变成显式、可回看、可带走的关系资产。**

## 二、设计原则（哲学落到工程）

1. **事实与表达分离的延伸**：关系事实由状态机/规则层记账——零 API、确定性、可回放；LLM 只朗读事实，永不产生事实。模型换一次，过去不会没（架构性保证，不是纪律性希望）。
2. **Append-only**：人生账本只追加、永不淘汰。与 `engine.events`（30 条工作记忆）严格区分：一个是 RAM，一个是墓志铭。
3. **资产可携带是一等契约**：一键导出/导入。任何未来的换栈、换模型、重装，迁移的单位是"关系资产包"，不是数据库碎片。
4. **低频，必须有重量**：纪念日/纪念卡沿用破局者彩蛋的设计原则——触发率低，情感密度高。

## 三、方案总览

### 3.1 人生账本 life.db（P0，全部零 API）

新增 `shared/life_ledger.py` + `data/life.db`（SQLite，模式参照 conversation_store）：

```sql
life_events(
  id INTEGER PRIMARY KEY,
  ts TEXT,                -- ISO 时刻
  kind TEXT,              -- genesis|first_name|loyalty_lock|reunion|breaker|
                          -- arc_shift|milestone|letter|scene_first|festival|
                          -- days_milestone|custom
  title TEXT,             -- 一句话（如"第一次收到蕾姆的来信"）
  detail TEXT,            -- 快照：arc/favor/period/weather/scene
  dedup_key TEXT UNIQUE   -- 幂等键（回填/重跑不重复记账）
)
```

**记账来源（自动镜像，引擎保持纯净）**：
- 引擎重要时刻：`name_first / locked / reunion / breaker`（在 bridge/gui 持久化层镜像，`_add_event` 仍是唯一判定真源）；
- 篇章切换 `set_arc`、名场面 `consume_milestone`、场景首访、来信接收；
- 日历类：相识日（genesis）、相识第 100/N 天、共同节日（见 3.2）。

**回填（M1 内一次性迁移）**：从 conversations.db 首条消息、engine.events、来信记录生成初始账本，幂等键去重。

### 3.2 纪念日引擎（P0，纯计算）

- 相识 N 天 / 百日 / 周年；"第一次"类周年（第一次来信、第一次锁定）；
- 节日表：**内置 2026–2030 静态对照表**（春节/元宵/七夕/中秋/端午为农历，避免引入农历依赖库）+ 公历节日（元旦/情人节/圣诞）；
- 输出两类事实：`今天是什么日子`（注入当日对话）与 `即将到来`（提前 3 天预告，可被来信系统引用——来信知道"快过节了"）。

### 3.3 当日事实注入 + 纪念卡（P1）

- PromptBuilder 新增 `_build_anniversary_section`：小节、事实化（"今天是你们相识的第 500 天"/"这是你们一起度过的第二个春节"）——双子"知道今天是什么日子"成为**行为**而非文案；
- 纪念卡：纪念日/名场面达成时，经 VignetteGenerator 生成一张卡（registry 新 slot `memorial`，L1 LLM 生成 + L2/L3 模板兜底——**离线也有卡**），落盘 `data/album/YYYY-MM-DD_标题.md`（含日期、arc/favor/天气快照、正文）；聊天内以 vignette 变体卡呈现。

### 3.4 回忆之书 UI v0（P1，顺带启动 God File 拆分）

- 新 Overlay（复用 HistoryOverlay 模式），**独立新模块**（拆分 gui.py 的第一块）；
- 顶部统计条：`同行 N 天 · M 轮对话 · K 封来信 · J 个被记住的瞬间`；
- 三页签：**时间线**（life_events 倒序）/ **纪念日**（已过+即将）/ **相册**（album 卡片列表）；
- 入口：主窗口快捷按钮（对应概念稿侧栏「回忆之书」位）。

### 3.5 关系资产导出/导入（P1，"时间不能丢"的工程保证）

- 导出：`data/` 全量（memory.json + conversations.db + life.db + world 状态 + album/）→ `ReZeroTwin-Life-YYYYMMDD.zip`；
- 导入：schema 校验 → 恢复 → 重启自检；
- 同时提供 `tools/export_life.py` / `tools/import_life.py`（无 GUI 可用）；
- forensic 埋点：`LEDGER_APPEND / LIFE_EXPORT / LIFE_IMPORT`。

## 四、验收 = V15.0 完整审判循环（Phase 3 制度化验收）

按审判循环设计 §5 Phase 3：**V15.0 走一次完整循环**——

1. 三委员会全跑：角色委员会（纪念日场景语感 / 纪念卡兜底）/ UX 委员会（回忆之书 4 任务 + 满意度问卷**新增"关系资产"维度题**）/ 压力委员会（500 轮长会话 + 回填幂等 + 导出导入往返）；
2. `trial_gate` 门禁：pytest 全绿 + 黄金剧本 diff + 指纹漂移（对 V14.9 基线）；
3. 新增探针：构造存档模拟纪念日 → prompt 含事实注入 / 无 key 纪念卡 L2/L3 兜底 / 导出→清空→导入→状态等价断言。

## 五、里程碑（每步可独立验收）

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M1 | life_ledger + 回填 + 记账镜像钩子 | 零 UI；pytest 全绿；回填幂等（跑两遍账本不变） |
| M2 | 纪念日引擎 + 节日表 + prompt 注入 + 纪念卡 + album | 离屏测试；无 key 出卡；prompt 断言 |
| M3 | 回忆之书 UI v0（新模块） | 离屏 4 任务；统计条数字与库一致 |
| M4 | 导出/导入 + forensic 埋点 | 往返等价断言；损坏包拒绝 |
| M5 | 完整审判循环 + CHANGELOG + EXE 打包发布 | Phase 3 验收台账可追溯 |

## 六、明确不做（V15 防扩权）

- 截图/视觉资产自动生成（等 V16 表现层，先留 album 卡片字段）；
- "突然想回看"的情感资产推荐（等数据积累，V17+）；
- 多档案/多用户、云同步、向量化 RAG（账本不为检索而生，为证明而生）；
- Live2D（决策点在 V17 后，依据 V16 视觉满意度数据）。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 相识日语义（最早消息 vs 存档创建） | genesis 取"最早可得证据"（conversations 首条 ts，回退 memory.json 创建时间），记账后永不改写 |
| 农历节日错误 | 静态对照表入库 + 单测逐年校验（2026–2030 硬编码即测试） |
| 回填重复/遗漏 | dedup_key 幂等 + 回填报告（新增/跳过计数）留档 sessions/ |
| gui.py 继续膨胀 | 回忆之书强制新模块落地，作为 God File 拆分第一刀 |
| 纪念卡打断对话流 | 沿用 vignette 的 View-Only 纪律 + 当日至多 1 张 + 可在设置关闭 |

## 八、版本路线修正案（与本构思一并确认）

```
V15.0 年轮（本版）：关系资产——账本/纪念日/纪念卡/回忆之书/导出导入 + 完整审判循环
V16.0 表现层：概念稿静态复刻（QML 舞台 + 玻璃 token + 分层背景）+ 截图基线入门禁
V17.0 动态化：呼吸/眨眼/动效/天气→粒子/环境音 + Scene Engine 泛化
V18.0+ 决策点：Live2D（依据 V16 视觉满意度数据）／技术栈换壳（依据资产契约迁移演练）
```

> 技术栈决策（C#/C++/Unity）继续挂起至 V18 决策点；本版交付的导出/导入契约就是那次决策的**前置条件**——先证明"时间能整体带走"，再谈换壳。
