# 设计考古：Rythum 4K 黑盒分析
### 从「音游 UI」到「角色生命体 UI」的迁移方案

> 考古对象：Rythum Game - 4K（流萤主题音游，小东朋友的个人项目）
> 考古方法：黑盒分析（运行表现 + 文件结构 + 视觉观察），**未读取/复制源码与资源文件**
> 证据等级：[观察] = 视觉/运行实测　[推测] = 基于行为的合理推断
> 日期：2026-08-06　产出：Re:Zero Twin Design System V2 输入材料

---

## 0. 一句话结论

> 它「精致」不是因为素材多，而是因为**审美预算纪律**：大面积低饱和底色、小面积高饱和强调、统一圆角语言、克制的弥散光影——以及把**角色人格注入 UI 行为**（破框头像、情感化文案）的能力。这两件事与素材无关，与设计系统有关，全部可迁移。

---

## 1. 技术架构推测（黑盒证据）

### 1.1 技术栈：Tauri 2.11.5（Rust 核心 + WebView2 前端）

| 证据 | 说明 |
|---|---|
| exe 内字符串 `tauri-2.11.5/src/plugin.rs` 等 [观察] | 明确 Tauri 2.11.5，非 Electron/Unity/Qt |
| `__TAURI_INVOKE__`、`tauri://resize` 等 IPC 特征 [观察] | 标准 Tauri IPC 模式 |
| `C:\Users\30518\.cargo\registry\...` [观察] | Rust 编译痕迹，开发者本机用户 30518 |
| 前端特征字符串（Vue 系）、`index.html` [观察] | 前端为 Web 技术，资源整体编入 exe |

**架构含义**：
- **性能敏感逻辑在 Rust**（谱面解析、判定、音频调度），**UI 全在 Web**（CSS 动画、布局自由度高）——音游判定精度与 UI 迭代速度兼得。
- 前端是 WebView2：视觉迭代成本极低（改 CSS 即改观感），适合快速打磨视觉。

### 1.2 内容外置架构：程序是壳，内容是活

```
RythumGame/
├── rythum-game.exe      (39MB，程序本体)
├── uninstall.exe
└── _up_/beatmap/        (31MB，全部游戏内容)
    ├── _song_29420/0/1689230128.mc + Background.jpg + *.ogg
    ├── _song_31020/0/...
    └── ... (按歌曲 ID 寻址)
```

- 谱面 `.mc`（Malody 系格式）+ `.ogg` 音频 + `.jpg` 背景 [观察]
- **新增一首歌 = 拷贝一个目录**，无需重新打包 exe → 热更新内容、独立迭代 [推测]
- 程序 39MB vs 内容 31MB：内容与程序解耦，扩展成本趋近于零

**这是小体量个人项目最值得抄的架构决策**：内容（角色资产）与程序（逻辑壳）分离。

### 1.3 设计系统落点（视觉侧）

视觉描述中高度一致的 Card / Badge / Button 原子组件（同 token 复用）[观察] → 前端存在明确的设计 token 体系（色板、圆角、阴影统一），这是「界面看起来完整」的技术原因。

## 2. 视觉系统拆解：为什么「精致」

### 2.1 色彩：马卡龙色系 + 低饱和 Mesh Gradient

- 主色薄荷青绿（Mint/Teal）+ 辅助鲑鱼粉（Coral Pink）+ 柔和浅黄 [观察]
- 大面积低饱和渐变网格背景 + 小面积高饱和强调（主 CTA 渐变胶囊）[观察]

**规律：饱和度预算制。**
> 背景层饱和度 ≈ 10–20%，强调层 ≈ 80–100%。用户感知「精致」的本质是——**高饱和被当作稀缺资源使用**，而不是到处用。

### 2.2 形状：胶囊（9999px）+ 超大圆角（24px+）

- 按钮全胶囊形、卡片 24px+ 圆角 [观察]

**规律：圆角半径 = 情绪温度。** 大圆角弱化攻击性，产出治愈/轻量气质。音游本可做硬核高光，它选了温柔路线——与角色（流萤）气质一致。

### 2.3 光影：弥散阴影 + 浮空卡片

- 不用重阴影，用浅色高斯模糊叠加柔和弥散阴影，形成「浮空卡片」[观察]

**规律：阴影的模糊半径 > 偏移量 → 轻盈立体；阴影偏移大 → 沉重。** 治愈系 UI 的阴影语法。

### 2.4 层级沉底：backdrop blur 模态

- 暂停弹窗用 `backdrop-filter: blur` 把背景沉底，焦点强制前置 [观察]

## 3. 交互与 UX 模式：可迁移的「为什么」

### 3.1 破框头像（Overflow Avatar）★ 全场最佳
暂停弹窗顶部流萤头像**溢出卡片边界**悬挂 [观察]。
> **为什么好**：常规 Modal 是「模板」，破框元素打破模板感，让角色「探出头来」——角色感来自对边界的突破，而不是贴图数量。

### 3.2 情感化文案（Emotional Copywriting）
放弃结算页：哭泣流萤头像 + 「没打完也没关系，再试试嘛」[观察]。
> **为什么好**：把负面事件（失败/放弃）转化为情感连接点。用户记住的不是「我输了」，而是「角色安慰了我」。这是把产品从工具推向关系的设计。

### 3.3 内嵌 Onboarding（按键映射卡直接上首屏）
主界面直接放 D/F/J/K 轨道、Esc 暂停、判定区间的按键卡 [观察]。
> **为什么好**：零认知门槛。教学不是弹窗打断，而是界面的一部分。

### 3.4 选中态语言（Active State）
选中歌曲：亮青色边框 + 右侧播放图标高亮 [观察]。
> 选中态 = 边框色 + 行为图标双重信号，清晰且不吵。

### 3.5 Metadata Badges（元数据徽章）
每首歌带 Pill Badges：难度 `4K LN`、`BPM 194`、Note 数 [观察]。
> 信息结构化：一眼扫完关键属性，排版紧凑。

### 3.6 按钮语义化（Semantic Buttons）
Primary 高饱和青色填充 / Secondary 白底微边框 / Destructive 红字粉框 [观察]。
> 用色彩语义防误触（退出是危险的，视觉上先警告）。

### 3.7 键盘无障碍（Keyboard Accessibility）
全程快捷键 + 显式提示（`R·再来一次`、`Enter·返回菜单`）[观察]。
> 音游本身是键盘应用，但提示显式化的习惯值得学：**快捷键存在 ≠ 用户知道**。

## 4. 迁移方案：Re:Zero Twin Design System V2

### A. 直接借鉴（附落地位置与优先级）

| # | 模式 | rezero_twin 落点 | 优先级 |
|---|---|---|---|
| 1 | **破框头像** | CharacterPanel：立绘/头像溢出面板上缘（配合 V13 灯火玻璃），角色情绪外显 | ★★★ |
| 2 | **情感化文案** | 拒绝/低好感/出错场景的安抚话术层，与 LLM 人格系统结合（View-Only，save=False 铁律内） | ★★★ |
| 3 | **状态徽章组** | 右拉姆面板：好感度/情绪/记忆数 Pill Badges（现有状态区徽章化） | ★★ |
| 4 | **选中态语言** | 角色切换、历史条目选中态：角色色边框 + 行为图标 | ★★ |
| 5 | **弥散阴影+浮空** | BubbleWidget / ChatMessageWidget 层级：阴影模糊>偏移，浮空卡片化 | ★★ |
| 6 | **按钮语义化** | 危险操作（清空记忆/退出）红语义防误触；主操作角色色填充 | ★★ |
| 7 | **键盘无障碍提示** | 底部快捷键提示条（Ctrl+1/2 切角色、Ctrl+L 历史），显式化 | ★ |
| 8 | **内嵌 Onboarding** | 首次启动角色引导卡（代替弹窗教学） | ★ |
| 9 | **饱和度预算制** | 检查现有 UI 高饱和面积：背景层压到 10–20%，强调留给角色色 | ★★★ |
| 10 | **内容外置架构** | 角色资产目录化（立绘/语音/表情外置可热更），中期架构项 | ★★ |

### B. 不适合的地方（及原因）

| 不借鉴 | 原因 |
|---|---|
| 马卡龙亮色系 | rezero 已定**暗色宅邸基调**（V13）：陪伴场景夜用为主，低刺激优先 |
| 高频动效/光效 | V13 动效原则：克制、服务沉浸——音游是分秒级高刺激，AI 陪伴是分钟级呼吸 |
| 高密度信息 HUD | 陪伴型 UI 需要低信息密度，拒绝仪表盘化 |
| 引入 Web 技术栈 | 工程铁律：不引入新 UI 框架（PySide6 生态已成型） |
| Mesh gradient 背景 | 灯火玻璃材质（V13）已是更贴合角色的方案 |

### C. 超越路径：从「音游 UI」到「角色生命体 UI」

音游的 UI 目标是**瞬态高刺激**（分秒级反馈）；AI 角色桌面的目标是**持续在场感**（分钟级呼吸）。照搬前者会毁掉后者。

**三层升级路径**：

```
L1 界面好看（视觉层）   ← 借鉴本报告 A 类条目：破框、徽章、阴影、语义按钮
L2 角色在场（存在层）   ← 破框头像不是装饰，而是情绪外显：开心时冒头、emo 时垂眸
L3 生命体感（关系层）   ← 情感化文案 × 记忆 × 人格联动：失败被安慰、被记住、被回应
```

**rezero_twin 独有优势（音游没有的）**：LLM 人格 × UI 状态联动。
- 音游的破框头像永远是同一个表情；rezero 的破框立绘可以随情绪/对话内容变化。
- 音游的「没打完也没关系」是写死的文案；rezero 可以是由状态机触发、LLM 生成的**属于当下情境**的安抚。
- 方向：**把 UI 做成角色身体的延伸**，而不是角色图片的容器。

## 5. 下一步建议

1. **V13.1 试点（纯观感，小步）**：破框头像 + 弥散阴影 + 状态徽章组——三个条目正好对应 CharacterPanel / BubbleWidget / 右拉姆面板，互不耦合，可分别验收
2. **情感化文案层**：与状态机事件（拒绝/低好感/出错）挂钩的轻氛围话术，遵守 View-Only 铁律
3. **中期架构**：角色资产目录外置化（参考 beatmap 结构，`assets/<角色>/<表情|语音|立绘>/`）
4. 若需进一步验证技术推测（前端组件结构、动画实现），需与小东确认边界后再解包
