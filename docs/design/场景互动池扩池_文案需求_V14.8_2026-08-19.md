# 场景互动池扩池 · 文案组需求文档（V14.8 候选）

> 日期：2026-08-19 ｜ 提交方：开发侧 ｜ 对接：文案组
> 背景：体验设计审查（docs/design/体验设计审查_2026-08-19.md）发现——场景互动池 100% 宅邸化、无 arc 维度，帝国/后期篇用户触发场景时注入宅邸文案（篇章失衡）。
> 原则：一切以 Re0 原著为基底；每篇章场景语感严格区分（宅邸女仆日常 / 帝国失忆疏离 / 后期战友托付）。

---

## 一、需求总览

### 1.1 场景互动池加 arc 维度（结构改造，开发侧做）

```
当前：scene_dialogue.json = { KITCHEN: { MORNING: {opening, interaction_1, interaction_2}, ... } }
目标：scene_dialogue.json = {
  mansion_era: { KITCHEN: {...}, ROOM: {...}, ... },   # 现有 7 场景保留
  empire_era:  { CAMP: {...}, INN: {...}, WILDERNESS: {...} },  # 帝国新场景
  late_arc:    { CAMPFIRE: {...}, BARRACKS: {...}, BATTLEFIELD: {...} }  # 后期新场景
}
```

- 现有宅邸场景保持原样（零改动，防回归）
- 帝国/后期各新增 3 个专属场景（场景键由开发侧定，见下）
- 场景切换识别：帝国篇「去营地/去旅店/去荒野」，后期篇「去营火/去军营/去战场」——关键词由开发侧扩展

### 1.2 场景键与语感要求

| arc | 场景键 | 场景 | 语感基调 |
|---|---|---|---|
| empire_era | `CAMP` | 营地 | 失忆疏离——蕾姆礼貌克制、不认人但隐隐熟悉；拉姆警戒护妹 |
| empire_era | `INN` | 旅店 | 旅途暂歇——陌生环境、谨慎观察、雨夜烛火 |
| empire_era | `WILDERNESS` | 荒野 | 帝国荒原——风沙、孤独感、蕾姆迷茫、拉姆警惕 |
| late_arc | `CAMPFIRE` | 营火 | 战后休整——战友并肩、篝火夜话、疲惫与信赖 |
| late_arc | `BARRACKS` | 军营 | 战前准备——整备武器、绷带、克制的托付感 |
| late_arc | `BATTLEFIELD` | 战场边缘 | 战斗间隙——警惕、守护、拉姆的剑与蕾姆的角 |

### 1.3 每场景文案量要求

| 字段 | 数量 | 格式 |
|---|---|---|
| opening（场景开场） | 每场景 1 条 | `rem_view` + `ram_view` 各 1 句（≤60 字/句） |
| interaction（互动引导） | 每场景 **3-5 条** | `rem_view` + `ram_view` 各 1 句 |
| 时段 slot | 每场景 2-3 个 | 见 §2 时段划分 |

**共需**：6 新场景 × (1 opening + 3-5 interaction) × (rem+ram) ≈ **48-72 句**（3 arc 分摊）

## 二、时段 slot 划分建议

| 场景 | 时段 slot | 说明 |
|---|---|---|
| CAMP（营地） | DAY / NIGHT | 昼行军、夜扎营 |
| INN（旅店） | DAY / NIGHT | 昼赶路、夜投宿 |
| WILDERNESS（荒野） | DAY / NIGHT | 全天候（风沙/星空） |
| CAMPFIRE（营火） | NIGHT / DEEP_NIGHT | 篝火主要在夜晚 |
| BARRACKS（军营） | MORNING / EVENING | 晨操练、暮整备 |
| BATTLEFIELD（战场） | DAY / NIGHT | 战时/战后 |

## 三、语感红线（OOC 自查）

| arc | 禁止 | 允许 |
|---|---|---|
| 帝国 | 深情告白、女仆腔「客人大人」、宅邸意象（红茶/花园/被单） | 疏离敬语、礼貌询问、隐隐熟悉感、「您似乎……认识蕾姆？」 |
| 后期 | 早期「可疑的客人」口吻、过度甜腻 | 战友称呼、并肩托付、「蕾姆在您左边」、克制的深情 |

## 四、开发侧对接项（非文案，已/将做）

1. **arc 维度结构**：scene_dialogue.json 顶层加 arc（开发侧做，文案组只填内容）
2. **场景切换关键词**：帝国/后期场景词加入 `SCENE_KEYWORDS`（开发侧）
3. **`_derive_location` 扩展**：新场景地点映射（开发侧）
4. **场景切换联动事件（O-1）**：切场景时若事件地点冲突则刷新（开发侧，待做）

---

## 五、交付格式约定

- 纯中文，蕾姆第三人称 / 拉姆傲娇区分（沿用 V14.6 角色卡语感）
- JSON 键名开发侧定，文案组只填 `rem_view` / `ram_view` 字符串
- 每条 ≤60 字，一段话（可含 1-2 个「……」停顿）
- 分批：先帝国 3 场景（优先级高——letters 帝国已 3 条，场景补上即可对齐），再后期 3 场景
