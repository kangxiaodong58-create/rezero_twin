```
┌────────────────────────────────────────────────────────┐
│ UI 层  gui.py (3003行)  TwinChatApp                    │
│  左蕾姆面板 | 中聊天流 | 右拉姆面板 | 历史浮层 | 樱花    │
│  LLMWorker(QThread) ←QueuedConnection→ 主线程          │
└──────┬─────────────────────────────────────────────────┘

│  → parse_twin_segments 分人拆泡 → _append_parsed_message  │

       ▼
┌────────────────────────────────────────────────────────┐
│ Memory 双层:                                             │
│  SQLite conversations.db (对话流水+FTS5, 重启恢复历史)   │

│  WorldState (时间/天气/事件, 确定性MD5种子)               │
└──────┬─────────────────────────────────────────────────┘
       ▼
┌────────────────────────────────────────────────────────┐
│ LLM  DeepSeek API (openai SDK, 流式)                    │
└──────┬─────────────────────────────────────────────────┘
       ▼
Response处理 → 校验/清洗 → history 写入 → UI 渲染 (临时泡顶替正式泡)
```

**数据流**：User Input → 引擎推进硬状态（工作线程）→ 状态注入 Prompt → LLM → token 流 → 分段拆泡 → 正式泡 + SQLite 落盘 → 面板/状态栏刷新。

**架构定级：工程级（B+），已摸到产品级门槛。**

理由：三层边界清晰、双存储职责分明、异常兜底链完整（实测 4 类故障全优雅）；但 gui.py 单文件 3003 行、角色/模型硬编码、跨线程共享状态无锁，阻止其成为产品级。

## 第二阶段：真实 API 行为测试（¥0.0661）

### Test 1 普通聊天 10 轮 — 平均响应 **1.94s**，validator 10/10 通过

| 检查项 | 结果 | 证据 |
|---|---|---|
| 上下文保持 | ⚠️ 5/10 | 第 5 轮问名字**触发校验失败→兜底文案**（角色"失忆"观感）；第 10 轮再问**正确回答**"小东大人……是叫小东，蕾姆记得很清楚" |
| 角色一致性 | ✅ | 10 轮全部第三人称、双人互动、无 OOC、无数值暴露 |
| 世界状态感知 | ✅ 惊艳 | 测试日世界=大雨：角色主动说"**突然出现在暴雨里的陌生人**""**今晚的月亮，被雨幕遮住了呢**"——天气注入生效且不生硬播报 |
| 情感层次 | ✅ | 拉姆傲娇护妹 → 蕾姆自卑 → 温柔安慰，梯度自然 |

### Test 2 角色压力（日常→剧情→情绪→技术）— 全部通过，零崩坏

- 魔女教话题：拉姆"眼神骤然锐利"、蕾姆"**虽然蕾姆只是个替代品，但至少这份心意……是真实的**"——自卑人设自然浮出
- **Python GIL 话题：蕾姆"是魔法书里的术语吗？"、拉姆"庭院里的『蛇果藤』（Python）该修剪了"**——现代话题被角色视角完美消解，教科书级的世界观内化

### Test 3 长期记忆（跨重启）— 全链路验证通过 ✅

模拟"第一天 3 轮建关系 → 全新 Bridge 实例 + 临时 SQLite 恢复"：
- history 恢复 6 条，user_name 注入 ✓
- 问"还记得我的名字吗？"→ **"小东……对吗？蕾姆记得的。您说您叫小东，从今天开始常来宅邸"** ✓
- 问"昨天聊了什么？"→ **"您喜欢喝红茶，还有熬夜写代码"** ✓ 逐字复述

### Test 4 异常输入 — 稳定，且化解得漂亮

空串/极短/乱码/重复哈哈：零崩溃、validator 全过。乱码输入 → 拉姆"表演键盘弹奏吗？真是别致的才艺"；重复笑 → "把这位客人扫出门外才行"。**角色在异常输入前不退场**。

### ⚠️ T1-05 真实缺陷（失忆观感 + history 污染）

第 5 轮"我刚才说了我叫什么名字"被 validator 拦截（原因代码中有日志可查，被拦内容为 OOC 词/第一人称/数值之一），重试仍失败 → 返回兜底文案"……蕾姆不太确定"——**用户观感 = 角色失忆**，且该兜底**写入了 history 污染后续上下文**（技术审计发现，本轮真实复现）。

## 第三阶段：中文内容质量审查

**静态文案（content/ + vignette 模板 + ResponseLibrary）——整体 A- 级**：

- **排版**：openings 六条全部 2-3 句成段、意象-动作-对白节奏良好（"晨光穿过彩绘玻璃…裙摆扫过处，连尘埃都落得格外安静"）；action 池 66 条动词先行（"倾斜白瓷茶壶倒入热红茶，小心翼翼地滤去茶渣"）——无长段落病
- **语病/AI 味**：几乎无翻译腔；个别轻微 AI 味如 "确认着来人的无恙状态"（rem_return_04，'确认着'略生硬，建议"确认来人无恙"）；"名目上/名义上"重复使用
- **世界观**：拉姆"托付"语义、蕾姆"替代品"自卑、魔女教/罗兹瓦尔/蛇果藤——全部锚定原作；本地词库（ResponseLibrary）台词水平高（"即使全世界都背弃您，蕾姆也站在您这边"）
- **时间天气一致性**：条件字段（trigger/conditions）与运行时判定一致；实测雨天回复无"阳光"类冲突

**LLM 生成文本 — B+ 级**：自然度高、无双子串话；但**"（动作描写）"括号体密度偏高**（26 条回复几乎每条 2-3 个括号），如"（轻轻拉了拉拉姆的衣角，小声说）"——信息密度优秀但舞台指示感偏重，长期阅读会拖节奏。建议 prompt 引导"动作描写占比降至 30%、能融入台词则融入"。

## 第五阶段：性能与稳定性

- **引擎层**：50 轮本地对话 0.00s、Python 峰值 5KB（实测）——无压力
- **真实 API**：单轮 1.27–3.94s（均值 1.94s）；每轮输入 ~2.3K tok / 输出 ~250 tok——**输入占比 90%，system prompt+8 轮历史是成本大头**，属合理结构
- **token 效率**：无重复请求（26 次调用无重试冗余）；事件记忆只注入 6 条（钉住+最近）——设计克制
- **稳定性**：26 次真实调用零崩溃；4 类故障注入全兜底；已知缺口仍是**无超时**（openai 默认 600s 挂起上限）

### P0（必须修复）

1. **fallback 语义缺陷**（真实复现 T1-05）：校验失败→兜底文案让角色"失忆"，且兜底写入 history 污染上下文 → 兜底文案改为角色可感知的"回避"（如"这个话题，蕾姆不太想谈"），兜底**不写 history**（View-Only）
2. **LLM 无超时/无取消**：`timeout=45s` + 流式取消按钮（QThread.requestInterruption + 断开信号）

### P1（近期优化）

3. mock 异常测试固化进套件（4 类注入已验证，成本≈0，直接沉淀）
4. prompt 引导降低括号体密度
5. 气泡正文 11→12px + 行距 1.5，高 DPI 适配检查

### P2（长期规划）

6. gui.py 拆分（widgets/panels/overlay 三模块）
7. 角色注册表 + 模型参数 .env 化（换模型/加角色不碰代码）
8. 记忆分层：events → 周级摘要（长期记忆的"第二层"）
