- **根因**：`gui.py:1844`（`_create_bot`）在无 key 时 `raise ValueError`；9 个 `test_ui_offscreen.py` 用例都构造 `TwinChatApp` → 直接失败。
- **为什么 CI / 之前的「干净克隆」验证没暴露**：`ci.yml` 的 job `env` 里有 `DEEPSEEK_API_KEY: test-key-not-used`；我此前的克隆验证也手工 `export` 过同款 dummy key。**本轮把「无 key」这种裸环境单独跑了一遍，才暴露出来。**
- **性质**：**测试套件不自足**——它隐式依赖「环境中已有一个 key（不论真假）」。这既是复现性缺口（新克隆者必须自己知道要设这个变量），也让「干净 checkout 跑通」这条判据在字面意义上不成立。
- **登记**：**A19 [P2]**（见架构 Spec 台账 A′ 段）。
- **修法（待批准）**：`tests/conftest.py` import 期 `os.environ.setdefault("DEEPSEEK_API_KEY", "test-key-not-used")`——与既有 `REZERO_GUI_LOG` / `REZERO_LIFE_DB` 同款做法；**不覆盖已有真实 key**（`setdefault`），测试零 API 调用不受影响。SPEC 草案：`SPEC-20260922-08`。
