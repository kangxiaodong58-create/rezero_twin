## 一、现状盘点

代码结构（git 追踪中，工作区干净）：

```
main.py            CLI 入口（默认 local）
gui.py             Tkinter GUI（默认 llm）
llm/bridge.py      ReZeroLLMBridge（状态机 + DeepSeek）
local/rem_ai.py    RemAI 本地模板蕾姆
local/twin_system.py  ReZeroTwinSystem 本地双子总控
shared/state.py    HardStateEngine + TwinState + 枚举
shared/prompts.py  PromptBuilder + ResponseLibrary + RamAI
shared/memory_store.py  JSON 持久化
```

架构评价：硬软分离的骨干是健康的——HardStateEngine 管数值、PromptBuilder 管状态转指令、LLM 只负责台词。设计哲学落地正确，不需要也不应该推倒。

## 二、诊断发现（按优先级）

### P0 安全

1. **API Key 被打进 EXE**：`ReZeroTwin.spec` 中 `datas=[('.env', '.')]` 把含真实 DEEPSEEK_API_KEY 的 .env 嵌入 EXE。若 EXE 分发（GitHub Releases / 发给别人）等于泄露密钥。另外该 key 已明文出现在本地开发日志中，建议去 DeepSeek 后台轮换。

### P1 逻辑 bug（能跑，但行为不正确）

2. **状态查询会推进状态机**：`gui.py:update_status()` 与 `llm/bridge.py:status()` 都调用 `engine.update("")`。空输入同样触发：鬼化余韵 -1、连续负面衰减。GUI 每条消息后都调 update_status → 状态机每轮"空转"一次，鬼化余韵衰减速度翻倍。方案：新增只读 `snapshot()`，显示走快照，`update()` 只在真实输入时调用。
3. **本地模式鬼化余韵是死代码**：`RemAI._oni_aftermath` 永远是 0（从未被赋值，`_sync_from_engine` 不同步它），余韵分支永远进不去。engine 自己的 oni_aftermath 正常工作，但 RemAI 用的是自己的计数器 → 本地模式永远看不到余韵台词。
4. **本地模式拉姆好感不持久**：`RamAI._favor` 与 `engine.ram_favor` 是两套数据。GUI 持久化的是 engine 的，RamAI 的重启后归零（永远回到 8/可疑）。

### P2 一致性 / 体验

5. **main.py 默认仍是 local**，与 GUI/MemoryStore 默认 llm 不一致（README 未说明）。
6. **GUI 在 LLM 模式会卡界面**：`bot.chat()` 网络调用跑在 Tkinter 主线程，API 延迟期间窗口假死。方案：后台线程 + `root.after` 回调。
7. **LLM 对话上下文不持久**：`bridge.history` 只在内存，重启后 LLM 丢失近期对话（chat_history 仅用于显示）。
8. **`/llm` `/local` 切换指令未实现**（旧日志写了"如已实现"，实际没有）。

### P3 工程化（低成本）

9. 缺 `requirements.txt`。
10. 缺冒烟测试（现有 test_mode.py 被 gitignore 且只测 mode 字段）。
11. 10+ 篇开发日志散落根目录（已 gitignore，按约束8不删除，可移入 docs/devlog/）。
12. `README_old.md` 同上。
