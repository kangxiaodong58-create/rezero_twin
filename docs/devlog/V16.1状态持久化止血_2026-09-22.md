## 2. 改了什么

### M2 · 引擎状态单源序列化（`shared/state.py`）
- 新增 `HardStateEngine.to_dict() / from_dict() / apply_dict()`，覆盖**全字段**：`arc / favor / locked / independence / recovery / ram_favor / oni_stage / oni_aftermath / witch_scent / user_name / consecutive_negative / consecutive_procrastinate / is_reunion / breaker_triggered / turn_count / events / profile(name, patterns, context)`
- 有意不持久化：`_companion_gains / _companion_cooldown`（V13.1 设计：重启重置）
- `apply_dict` 同时接受**旧平铺格式**（V16.0 及以前），因此调用方可无条件传 `mem.get("engine") or mem`；坏字段/坏类型静默回落默认值（存档被手改也能启动）
- `gui.py::_create_bot` / `_save_state`、`main.py` 统一走该入口

**修掉的隐性数据蒸发**（V16.0 及以前的真实行为）：

| 字段 | 旧行为 | 新行为 |
|---|---|---|
| `locked` | `_save_state` 写了，`_create_bot` **不读** | 跨重启保留 |
| `oni_stage / oni_aftermath / witch_scent` | **根本不落盘** → 每次重启鬼化清零、魔女残香归零 | 跨重启保留 |
| `is_reunion / breaker_triggered` | 同上 | 跨重启保留 |
| `turn_count` | 从不落盘（仅内存） | 跨重启保留 |
| `consecutive_negative / consecutive_procrastinate` | 从不落盘 → `wants_push`、负面前置判断每次重启失效 | 跨重启保留 |
| `profile.context / patterns` | 从不落盘 → prompt 里的情绪轨迹每次重启为空 | 跨重启保留 |

### M1 · memory.json 原子写（`shared/memory_store.py`）
- 写：`.tmp` → `flush + fsync` → 备份上一代到 `.bak` → `os.replace(tmp, main)`；新档写 `schema_version=2`
- 读：三级降级，**绝不静默回默认值**
  1. 主档可解析 → 正常
  2. 主档坏、`.bak` 好 → 从备份恢复 + 原子写回主档 + `log.warning` + 取证 `SAVE_REPAIRED_FROM_BACKUP`

- 破坏性变更：无（`load/save/get/set/append_chat` 接口与语义保持；磁盘上多一个 `.bak`）

## 3. 意外发现：测试一直在写真实存档（已修根因）

**现象**：跑完测试后 `data/memory.json` 的 mtime 每次都变，内容出现新格式 `engine` 键。

**根因**（两层叠加）：
1. `shared/memory_store.py` 在 **import 期** `from .config import get_data_dir` 绑定函数对象，而 `tests/smoke_test.py::test_world_state_docx_compat` 用 `_config.get_data_dir = lambda: tmp` 打补丁 → **补丁对 MemoryStore 无效** → `save_world_state()` 写真实 `data/memory.json`（`world_state` 被测试世界覆盖）
2. `tests/test_motion.py` / `tests/test_status_dashboard.py` 构造主窗口时**未隔离** `MemoryStore/ConversationStore`，`win.close()` 触发 `_save_state()` 写真实存档

**影响范围**（实测核对）：
- 源码树存档 `data/memory.json`：`favor=23 / ram_favor=9 / independence=0.31 / events=2 / user_name=None` **数值全部完好**；`world_state` 的场景、来信冷却、日更问候标记、活跃事件、离线天数被覆盖
- **`dist/data/memory.json`（实际游玩存档，favor=33 / ram_favor=29 / user_name=为客人大人哦）未受影响**——它由打包版 EXE 读写，测试不会碰
- `data/life.db`（append-only 年轮账本，仅 1 条 genesis）**未被写过**

**修复**：
- `memory_store` 改为调用时解析 `config.get_data_dir()`（符合项目"晚绑定"纪律）
- 两个测试补齐存储隔离 + `DEEPSEEK_API_KEY` 占位
- 新增回归用例 `test_memory_store_resolves_data_dir_late`
- 新增验收口径：**跑完测试后 `data/` 逐字节不变**（见 §4）
