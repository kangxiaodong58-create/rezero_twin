# v13.0 稳定版 P0（LLM 超时 · 线程收尾与取消 · 兜底不污染 history）

日期：2026-08-06
来源：V13.0 任务书（产品级验收 T1-05 等三缺陷 → 补工程铠甲；AI 层零改动）

## 修改内容

### `llm/bridge.py`（7 处，行为+边界）

1. **client 级超时**：`timeout=float(os.getenv("REZERO_LLM_TIMEOUT", "45"))`——一处覆盖 chat / chat_stream / raw_completion；超时=API 异常路径（原已不写 history，无需额外处理）。
2. **新字段**（`__init__`）：`_last_chat_fallback`（chat 本轮是否兜底）、`_last_stream_ok`（流式校验结果回传）、`_stream_fallback_text`（回避文案）、`_active_stream` / `_stream_cancelled`（取消通道）。
3. **`cancel_stream()`**：置取消标志 + 关闭底层 httpx 流；生成器下个检查点静默提前结束。
4. **`_fallback_reply()` 文案**：失忆感 → 角色内回避（「这个话题，蕾姆想先放一放」）。
5. **`_generate_validated()` → `(reply, is_fallback)`**。
6. **`chat()`**：`is_fallback` 时不写 history、不清首轮氛围、不写场景冷却（mark_interaction 保留）。
7. **`chat_stream()`**：每次调用重置流式状态；生成器内取消检查；校验结果回传 `_last_stream_ok` / `_stream_fallback_text`；`finally` 关流。

### `gui.py`（10 处，边界+UI 态）

1. `LLMWorker.cancel()`：`getattr(bot, "cancel_stream")` 防御调用。
2. `_teardown_llm_thread()`：统一收尾（disconnect → cancel → requestInterruption → quit+wait(2s) → terminate 最后手段 → 置空 → 清泡）。
3. `_cancel_streaming()`：取消入口（teardown + UI 恢复 + footer「已取消」）。
4. `_send_message()`：流式中发送键 = 取消（原「正在回复中」提示删除）；流式启动时按钮变「取消」。
5. `_send_llm_stream()`：原手写 quit/terminate 块替换为 `_teardown_llm_thread()`。
6. `_on_stream_finished()`：`_last_stream_ok is False` → 丢弃未校验全文 + 清临时泡 + View-Only 回避文案（save=False）。
7. `_parse_twin_reply()`：新增 `save` 参数（默认 True）。
8. `_finish_reply()`：按钮恢复「发送」。
9. `_switch_mode()`：开头 teardown + UI 态复位（修复流式中切模式的旧 worker 错对象读）。
10. `closeEvent()`：先 teardown 再存状态。

### `tests/test_llm_failures.py`（新建，10 用例）

- chat 4 类异常（断网/空响应/None/OOC）→ 不写 history
- **T1-05 回归**：校验失败兜底不写 history
- 成功路径回归（正常写 history）
- stream 异常/校验失败/成功 → 状态回传正确
- `cancel_stream()` → 生成器提前结束 + 不写 history
- 兜底文案防失忆感

## 行为变化声明

- 校验失败兜底 = **用户可见、上下文不可见**：不写 bridge.history、不落 ConversationStore（save=False）、不进后续 Prompt
- 流式中发送键 = 取消（不再是「正在回复中」提示）
- 关窗/切模式时旧 worker 不再可能回写 UI（先断开信号再回收线程）
- API 异常（断网/超时）文案保留「没听清」——语义真实（确实没收到），仅校验失败兜底改回避
- LLM 请求 45s 超时（`REZERO_LLM_TIMEOUT` 可覆盖）

## 踩坑记录

- **V4A 多 hunk patch 的 hunk 构造陷阱**：一次 `patch mode='patch'` 里 hunk 6 的 old/new 行交错了 `-`/`+`，导致整个 patch 验证失败回滚（文件原样，无部分写入——工具是原子验证）。教训：**复杂多 hunk 改用逐个 replace mode 串行**，每个 old_string 保持完整连续。
- **取消依赖「流中有下一个 chunk」**：`stream.close()` 中断阻塞读取（httpx 层），即使 API 完全无响应也会在关闭时解除阻塞；真正卡死的兜底是 45s 超时。两层闭环，不依赖 terminate。
- `_teardown_llm_thread` 不碰 `_streaming_active`：调用方语义不同（取消要置 False、`_send_llm_stream` 重入后要重新置 True），职责分离避免误伤。
