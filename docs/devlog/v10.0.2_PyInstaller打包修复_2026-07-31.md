# V10.0.2 PyInstaller 打包修复 — 2026-07-31

## 根因

PyInstaller 的静态分析无法检测到函数内部的懒加载导入：

```python
def _get_openai():
    from openai import OpenAI  # ← PyInstaller 看不到这行
    return OpenAI
```

即使 spec 中声明了 `hiddenimports=['openai']`，PyInstaller 仍漏掉了
`openai` 的 C 扩展子模块（`pydantic_core._pydantic_core` 等），
导致 EXE 中实际不含 openai 的二进制依赖，运行时 ImportError。

## 环境问题

两个 Python 环境并存：

| 用途 | 路径 | openai |
|------|------|--------|
| 运行时 (python) | Hermes venv | ✅ 已安装 |
| 旧构建 (pip→pyinstaller) | D:\python | ❌ 未安装 |

## 修复

### 1. spec 使用 `collect_all('openai')`

```python
from PyInstaller.utils.hooks import collect_all
openai_datas, openai_binaries, openai_hidden = collect_all('openai')

a = Analysis(
    binaries=openai_binaries,
    datas=[('assets', 'assets')] + openai_datas,
    hiddenimports=openai_hidden + [...],
)
```

`collect_all` 递归收集 openai 的所有子模块、数据文件和二进制依赖，
包括 pydantic_core 的 C 扩展 `.pyd` 文件。

### 2. 在 Hermes venv 中安装 pyinstaller

```powershell
python -m pip install pyinstaller
```

确保构建环境与运行时环境一致。

### 3. bridge.py 清理

- 移除冗余 `sys.path` 操作（在 PyInstaller frozen 下可能解析到错误路径）
- `gui.py` 已全局设置路径，子模块无需重复

## 验证

- EXE 从 66MB → 76MB（openai + 依赖已打包）
- 13/13 冒烟测试通过
- `from openai import OpenAI` 在 Hermes venv 中正常
