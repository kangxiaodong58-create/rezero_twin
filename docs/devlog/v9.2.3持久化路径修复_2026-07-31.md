# v9.2.3 持久化路径修复

日期：2026-07-31
commit: `fix: EXE 模式下持久化数据改存 EXE 同级 data/ 目录`

## 问题根因

PyInstaller onefile 下入口脚本 `__file__` 指向 `sys._MEIPASS`（临时解压目录），
`gui.py` 用 `dirname(__file__)` 作为 `MemoryStore` 根目录 → `data/memory.json` 写进
`_MEIPASS\data\`，程序退出即被清理，EXE 每次启动都是"失忆"状态。

实证：`%TEMP%` 下发现 8 个孤儿 `_MEI*` 目录，每个都有独立 `data/`。

## 修改内容

| 文件 | 改动 |
|------|------|
| `shared/config.py` | 新增 `get_data_dir()`：frozen → `dirname(sys.argv[0])/data`（OSError 兜底 `%APPDATA%/ReZeroTwin/data`）；非 frozen → 项目根 `data/`；返回前确保目录存在 |
| `shared/memory_store.py` | `root_dir=None` 时改用 `get_data_dir()`；显式传参语义不变 |
| `gui.py` | `MemoryStore(_PROJECT_ROOT)` → `MemoryStore()` |
| `README.md` | 打包章节补数据保存位置说明 |
| `CHANGELOG.md` | v9.2.3 条目 |

## 验证结果

1. py_compile 全部通过
2. 三场景断言脚本（v923_datadir_test.py）：
   - DEV_MODE_OK：`…\rezero_twin\data\memory.json`（与旧路径逐字节一致）
   - FROZEN_SIM_OK：`…\dist\data\memory.json`，写入→重开→数据仍在
   - FALLBACK_OK：模拟只读目录 → `…\AppData\Roaming\ReZeroTwin\data`
3. 真 EXE：重新打包后启动一次，`dist\data\` 自动生成（路径指向正确）
4. `main.py --mode local` / `--mode llm` 回归正常

## 备注

- `%TEMP%` 孤儿 `_MEI*` 目录未清理（用户知情，Windows 自清）
- CLI（main.py）不持久化属现状设计，本阶段不处理
