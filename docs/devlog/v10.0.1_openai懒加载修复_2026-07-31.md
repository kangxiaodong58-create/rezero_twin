# V10.0.1 openai 懒加载修复 — 2026-07-31

## 问题

切换模式从本地 → LLM 时报错：
```
切换失败：请先安装 openai 库：pip install openai
```

即使 `openai` 已正确安装（`pip list` 可见），切换仍然失败。

## 根因

`llm/bridge.py` 在模块顶层执行 `from openai import OpenAI`：

```python
# bridge.py 第 22-25 行（修复前）
try:
    from openai import OpenAI
except ImportError as _e:
    raise ImportError("请先安装 openai 库：pip install openai") from _e
```

当 `gui.py` 的 `_switch_mode()` 执行 `from llm import ReZeroLLMBridge` 时，
触发 `llm/__init__.py` → `from .bridge import ReZeroLLMBridge` → 模块顶层 `openai` 导入。

在 PyInstaller onefile 打包环境下，`openai` 的子模块可能未被全部收集到
`sys._MEIPASS` 中，导致模块级导入失败，即使开发环境正常。

## 修复

将 `openai` 导入改为**懒加载**——只在 `ReZeroLLMBridge.__init__()` 中首次使用时导入：

```python
# bridge.py（修复后）
def _get_openai():
    """懒加载 openai，避免模块级导入阻断切换模式。"""
    try:
        from openai import OpenAI as _OpenAI
        return _OpenAI
    except ImportError as _e:
        raise ImportError(
            "请先安装 openai 库：pip install openai\n"
            "如果已安装，请检查 Python 环境是否正确。"
        ) from _e

class ReZeroLLMBridge:
    def __init__(self, ...):
        ...
        OpenAI = _get_openai()  # ← 懒加载
        self.client = OpenAI(...)
```

同时 `gui.py` 的 `_switch_mode()` 新增 API Key 缺失检测：
```python
api_key = os.getenv("DEEPSEEK_API_KEY")
if not api_key:
    raise ValueError("未找到 DEEPSEEK_API_KEY，请确保 .env 文件在同目录下。")
```

## 影响

- `from llm import ReZeroLLMBridge` 不再依赖 `openai` 是否安装
- 本地 → LLM 切换不再因打包环境导入失败而阻断
- 13/13 冒烟测试通过

## 补充修复（同日）

- `llm/bridge.py`：移除冗余的 `sys.path` 操作（`_PROJECT_ROOT` 从 `__file__` 推导，在 PyInstaller frozen 环境下可能指向错误路径）。`gui.py` 已全局设置路径，无需每个子模块重复。
- `gui.py`：`_switch_mode()` 新增分步日志（含 traceback），`__init__` 记录 Python 解释器路径，便于追查环境问题。
