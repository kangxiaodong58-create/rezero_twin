## 二、提案没提但同源的两个事实（本轮实测补充）

- **右栏固定 320px 偏宽**（提案建议 260–288）：`LAYOUT['dash_w']=320`。它同时是**窄屏看不到右栏**的直接原因（三栏最小需求 ≈1440 逻辑宽；当前显示器 150% 缩放下逻辑宽仅 ~1133）⇒ **收窄右栏一举两得**（观感 + 可用性）。
- **`FONT_SIZE` 以 pt 计**（9/10/12）：在 150% DPI 下实际渲染 ≈ 13.5/15/18px，与提案的 12–13px/14–15px 建议接近；**问题在颜色对比与层级，不在字号本身**。

## 三、与现行状态的关系

- SPEC-25（立绘 + 头像 64px + B1 修复）**已实现**，处于「待真机确认」；本评估**不影响**其合并决定（立绘/头像属 P2 范畴，且是净改善）。
- 本评估产出的重整优先级，与 SPEC-22 剩余项（S4 结构守卫）**不冲突**：S4 是代码结构，P0/P1 是视觉系统。

## 五、决策点（请逐条给 a/b/c，或回「全取推荐」）

- **D1 聊天区表面**：**a) 改为深色玻璃面（与 chrome 统一，最高杠杆）** ｜ b) 保留浅色面但压暗降饱和 ｜ c) 保持现状
- **D2 右栏宽度**：**a) 320 → 288（顺势缓解窄屏）** ｜ b) → 260（更窄，卡片更紧凑） ｜ c) 保持 320 + 只做自适应折叠
- **D3 底部图标坞**：a) 删除（把底栏还原为纯状态栏，注意力 -1） ｜ **b) 保留但弱化（降亮度/减图标尺寸）** ｜ c) 保持
- **D4 好感度呈现**：**a) 弱化为「小字 + 进度条」** ｜ b) 保持数值 ｜ c) 移入开发者面板，卡片只留心情/正在做
- **D5 文字对比**：**a) muted/secondary 提亮至 ≥4.5:1 并重采 QSS golden** ｜ b) 只提 muted ｜ c) 保持
- **D6 消息流对齐**：**a) 少消息时贴底（标准聊天习惯），多消息保持自然滚动** ｜ b) 保持贴顶 ｜ c) 空态加引导文案

## 附：转发给其它 Agent 时的前置声明（《外部提案翻译纪律》要求）

> 本项目是 **PySide6 单机桌面应用**。外部 Web 提案只取概念、不取技术栈：React/组件树 → Qt Widgets + 布局；CSS Variables → `design_tokens.py`；QSS 主题 → `ui/theme.py`（单一真源）；Framer Motion → `QPropertyAnimation` + `motion.py`；react-virtual → 不需要（消息量级小，`QScrollArea` 足够）；WebSocket/Worker → 进程内调用/`QThread`。**禁止新建 Web 技术栈抽象层。**
