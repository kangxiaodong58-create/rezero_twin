## 1. 问题（审批 A2）

```
llm/bridge.py::_build_messages()
    state = self.engine.update(user_input)      # ← 状态在 API 调用之前就地推进
    ...
llm/bridge.py::chat()/chat_stream()
    reply = client.chat...create(...)           # ← 失败也回不去
```

后果两条：
1. 网络抖动 / 校验失败 / 用户取消的轮次**照样**涨好感、涨 `turn_count`、进鬼化阶段；
2. `state.py::_detect_events()` 在 `update()` 内已把 `first_name / loyalty_lock / reunion / breaker`
   等事实镜像进 **append-only 的 `life.db`** —— 账本可能记下「从未发生」的时刻，且无补偿通道
   （只有 `dedup_key` 幂等，没有删除/回滚）。

## 2. 方案（决策已定：world 即时，账本随提交）

| 层 | 何时落地 | 理由 |
|---|---|---|
| `world`（场景切换 / 时段 / 事件刷新 / `mark_interaction`） | **即时** | 用户动作即事实（小东 2026-09-22 决策） |
| 引擎数值（好感/轮次/鬼化/连续负面/…） | **commit** | 失败轮不得推进 |
| 账本事实（`first_name / locked / reunion / breaker / scene_first`） | **commit** | append-only，无补偿通道 |
| 取证轨迹（`engine.favor/locked/ram/oni` 跃迁） | **commit** | 崩溃现场不应出现「未发生」的迁移 |

实现：
- `shared/state.py`：新增 `TurnTxn` + `HardStateEngine.begin_turn()`；
  `_life_mirror(fn, sink=…)` / `_trace_transition(…, sink=…)` 支持入队延迟。
- `llm/bridge.py`：`_build_messages()` 改为 `txn = self.engine.begin_turn(user_input)`，
  本轮 prompt/profile 一律读 `txn.candidate`；`chat()` 与 `chat_stream()` 的成功路径
  `txn.commit()`，而 API 异常 / 校验失败 / 取消 / 流中断 / stale 会话 / 会话重置
  一律 `txn.discard(reason)`。
- 面板语义：`engine` 真身本轮不变 → GUI 读 `engine.snapshot()` 得到的仍是上一轮的值，
  数值在回复完成后统一刷新（**行为变化，需真机确认**）。

## 3. 施工中新发现（P1，已修）

**场景首访记账从未生效**：

```python
# llm/bridge.py（V16.1 之前）
try:
    from shared.life_ledger import mirror_scene_first
    mirror_scene_first(new_scene, arc_value)   # arc_value 从未定义！
except Exception:
    pass                                       # NameError 被静默吞掉
```

静态核验（AST 扫描赋值/使用）确认 `arc_value` 在 `_build_messages` 内既无赋值也无外层定义
→ 恒抛 `NameError`。证据：`data/life.db` 只有 1 条 `genesis`，尽管真机已多次切换场景。
现改为 `txn.defer_fact(lambda s=new_scene, a=arc_value: mirror_scene_first(s, a))`，
并显式从 `state.arc` 取篇章值。

## 5.5 V16.2.1 补丁：篇章指令报「未知指令」（真机确认阶段发现）

**症状**：`/empire` `/mansion` `/late` 一律回「未知指令: /empire」。

**根因**：`TwinChatApp` 里有**两份** `_handle_command`：

| 位置 | 内容 | 结局 |
|---|---|---|
| `gui.py` 上部（命令处理区） | 完整路由：status 富面板 + mansion/empire/late + toggle | **被覆盖 → 死代码** |
| `gui.py` 后部（历史浮层下方） | V16-M_D 导航栏精简版：只认 `/status` `/toggle`，其余「未知指令」 | 生效 |

Python 类体**后定义覆盖前定义**，且两份同名方法不报错、不告警、原 294 项测试照样全绿——
`_send_message` 把 `/mansion /empire /late` 交给 `_handle_command`，正好落进精简版的 else 分支。
副作用：V10.9.2 的富状态面板（篇章/独立/残香）自 V16.0-mf 起失效，`/status` 变成纯文本。

**修法**：
1. 删除后部那份重复定义，保留并加强上部唯一路由（try/except 守卫、`strip()` + 小写归一）；
2. 新增 `_apply_arc()` 统一「改状态 → 落盘 → 提示 → 标签/状态栏/面板」；
3. `_send_message` 的四处分散命令判断收敛为「`text.startswith("/")` → 唯一路由」；
4. 新增 `tests/test_command_router.py`：**结构守卫**（全项目 AST 扫重复方法名）+
   字面量覆盖断言 + offscreen 行为回归（含真实入口 `_send_message`）。

**为什么原测试没发现**：全部 GUI 测试只断言「窗口能建、面板有数、气泡能加」，
没有任何一条真的**驱动命令路由**；而重复定义在运行时不产生异常。

**扫描结论**：全项目 115 个 .py 里，同类重复方法定义仅此一处
（`shared/world_state.py` 里 `last_real_timestamp` 等三对是 `@property` + `@setter` 的正常写法，
守卫测试已按装饰器排除）。
