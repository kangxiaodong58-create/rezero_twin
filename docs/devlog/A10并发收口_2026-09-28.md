## §1 改了什麼（3 处）

1. **加锁（候选②）**：`HardStateEngine.__init__` 增 `self._lock = threading.Lock()`；
   `apply_dict` / `snapshot` / `to_dict` 三个公开入口整段持锁（实现体拆到 `_*_impl` 无锁方法，
   注释标明「勿直接调用」）。调用图核实**无嵌套持锁路径** ⇒ 普通 `Lock` 即最小必要（F21-5）。
2. **增量写回（补候选②短板）**：`TurnTxn` 新增 `base`（= `begin_turn` 时刻快照，与构造候选副本
   复用同一份 `to_dict()`，零额外开销）；`commit()` 计算 `delta = candidate - base` 后只写差集，
   不再整量回写。语义写死：**本轮改过的字段以本轮为准；本轮没碰的字段一律不动**。
3. **前置修正**：`apply_dict` 的 `user_name` 从「缺键 → None」改为「**键存在性**」语义
   （缺键保持当前值 / 显式 `None` 置空）——否则 delta 写回会把用户名误清空。
   另：`snapshot()` 的 `events=list(self.events)`，断开唯一共享容器引用（F21-1 补充项）。

## §5 坑与经验

1. **`verify_isolation.sh` 的 exit 127 假绿坑复现**：把被测命令写成**一个带引号的字符串** ⇒
   `line 24: ...: No such file or directory` + 脚本仍打印「✅ 数据隔离校验通过」+ 退出码 127。
   **正确用法是把命令按参数拆开传**：`bash scripts/verify_isolation.sh env -u PYTHONPATH venv/Scripts/python.exe -m pytest tests/ -q`。
   （脚本会先跑命令再比快照；命令没跑成功时「校验通过」没有意义——**看到 ✅ 必须同时确认退出码 0**。）
2. `apply_dict` 拆 `_apply_dict_impl` 的动机：Python 无「给函数体加锁」语法，逐行缩进 80 行风险高；
   公开入口薄包装 + 无锁实现体 = diff 最小且语义显式。
3. `events=self.events` 有两处（`update()` 内与 `snapshot()` 内）——本批只改 snapshot 侧
   （`update()` 的返回值在 worker 线程内消费，不与主线程共享）；patch 时须用后续 `def set_arc` 锚定区分。
