# V10.2.1 线程安全 + 历史搜索 — 2026-07-31

## 崩溃根因

第二轮对话时 EXE 崩溃，原因：

1. **并发发送无保护**：`_send_message` 未检查是否已有流式调用进行中。
   用户快速连发消息时，两个 QThread 同时操作 `_streaming_buffer` → 数据竞争。

2. **旧线程未清理**：每次 `_send_llm_stream` 创建新 `QThread`，
   但旧线程的 `finished` / `error` 信号仍连接在已被替换的 worker 上。
   旧线程结束后信号触发 → 回调访问已失效对象 → 崩溃。

3. **信号未使用 QueuedConnection**：跨线程信号应显式使用
   `Qt.QueuedConnection`，否则可能直接在 worker 线程执行 GUI 代码。

## 修复

### 线程安全

| 措施 | 实现 |
|------|------|
| `_streaming_active` 守卫 | 发送前检查，进行中则忽略新消息并提示 |
| 旧线程清理 | 发送前 `quit()` + `wait(2s)`，超时 `terminate()` |
| 旧信号断开 | 创建新 worker 前 `disconnect()` 所有旧信号 |
| QueuedConnection | 所有跨线程信号使用 `Qt.QueuedConnection` |
| 线程自清理 | `thread.finished.connect(thread.deleteLater)` |
