## 4. 根因定位（基于代码证据 + 平台差异推理）

- 本地 Windows：`295 passed`（同一提交 `290eb9f` 的工作区等价物）。
- 差异点筛查：Python 版本（本地 venv **3.10.11** ≈ CI 3.10，非主因）→ 3.11+ 专属 API（无）→ **平台专有写法**（命中）。
- **嫌疑点**：`tests/test_motion.py:37 / 84 / 94` 三处 `monkeypatch.setenv("QT_QPA_PLATFORM", "windows")`。
  - 存在原因：`motion.py:25` 规定「`QT_QPA_PLATFORM == offscreen` → 恒禁用」；三个**启用态**用例必须临时把平台改成非 offscreen，`motion.enabled()` 才会为 True。
  - 为什么在 Linux 会炸：若 QApplication 在环境变量被改**之后**才创建（或应用被 GC 后重建），Linux runner 会尝试加载**不存在的 `windows` 平台插件** → Qt 致命错误 → 整步失败、且失败文本淹没在进程 abort 输出里。

## 5. 修复（SPEC-20260922-10）

1. **可移植夹具**（不改变任何测试意图）：
   - `tests/conftest.py` 新增 **session 级 `qapp`** 夹具：pytest 的 scope 规则保证它在 function 级 `monkeypatch` **之前**建好 → QApplication 始终以 offscreen 起步；session 级引用同时避免应用被 GC 重建。
   - `tests/test_motion.py` 三个启用态用例 `(monkeypatch, qtapp)` → **`(qapp, monkeypatch)`**；断言零改动。
