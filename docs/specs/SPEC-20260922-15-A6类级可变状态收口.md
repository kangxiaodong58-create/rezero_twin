# A6 收口：scope 逃逸的类级可变状态

## 目标

把两处**类级可变状态**改为**实例态**，消除「跨窗口/跨测试共享」与「不可持久化」问题：

- **A6-1** `SceneManager._interaction_rotor` / `_last_interaction`（`shared/scene_manager.py:104-105`，在 **classmethod** `get_scene_interaction` 内读写 `:202-208`）→ 移交给**世界实例**持有；
- **A6-2** `ReZeroLLMBridge._anniv_cache`（`llm/bridge.py:249`，类级字典，读点在 `:254`）→ 改为实例字段。

## 为什么（现状危害）

`SceneManager` 的 docstring 自称「无状态查询 + 静态资产，线程安全」——**与事实不符**：轮转游标是类级共享的全局态。后果：① 多窗口/多实例互相踩（A 窗口的轮转影响 B 窗口）；② 测试间互相污染（`tests/test_long_session_stability.py` 直接 import 该类）；③ 重启后同一格互动从头开始（不可持久化——本 SPEC 保持该性质，但改为**显式声明**）。

## 非目标

把轮转游标**持久化**（有意不落盘，见下「注释纪律」）；改轮转算法（仍是「避开上次 + 取模轮转」）；改场景库 schema；动 `consume_milestone`（另有 24h 冷却，不在本项）。

## 方案（建议路线）

1. `shared/state.py` 的 `WorldState` 新增两个**有意不持久化**的运行时字段（`__init__` 内初始化，**不进** `save_dict/load_or_create`），并在字段旁注释写明理由：
   `# 有意不持久化：场景互动轮转游标（重启重置是设计选择，V14.7 O-4）`；
2. `SceneManager.get_scene_interaction(scene, period, arc=None, *, rotor=None, last=None)`——游标由**参数传入**（缺省时用私有模块级兜底并 `_log` 一次告警，保证旧调用不炸）；
3. 调用点 `shared/prompts.py:169` 传入世界实例的游标——**F15-1 已闭合：无需任何签名变化**。完整调用链（devlog §4）：

   ```
   bridge.chat_stream → bridge._build_messages (llm/bridge.py:159)
     → world = self.world or WorldState.now()  (:169)
     → PromptBuilder.build(state, world=world, …)  (:211)
       → shared/prompts.py:169 SceneManager.get_scene_interaction(world.scene, world.period, …)
   ```

   `PromptBuilder.build()` **本就接收 `world`**（`shared/prompts.py:141`），`world` 就在 `:169` 同一作用域 ⇒ 只需把新增的运行时游标字段作为**关键字参数**传下去；`prompts.py` 对外签名与 `llm/bridge.py:211` 唯一调用点**零改动**。其余调用点（`tests/test_v148_arc_scenes.py:27/31`、`tests/test_v14_7_scene.py:61/64/66`）不传游标 ⇒ 走模块级兜底，既有断言不受影响。
4. `llm/bridge.py`：`__init__` 内 `self._anniv_cache: Dict[str, List[Any]] = {}`，`:254` 改 `self._anniv_cache`。
