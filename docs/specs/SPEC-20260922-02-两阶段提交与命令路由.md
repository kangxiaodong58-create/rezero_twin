## 核心改动

### M3 两阶段提交

`engine.update()` 原本嵌在 `_build_messages()` 内、先于 API 调用执行 → 失败轮照样涨好感/涨轮次/进鬼化，并把「从未发生」的事实镜像进 append-only 的 `life.db`（无补偿通道）。

- `TurnTxn`：`begin_turn(text)` 在**引擎副本**上推进状态；`commit()` 才写回真身并落地账本/轨迹；`discard(reason)` 丢弃并记 `TURN_DISCARDED`
- 六条失败路径全部 discard：API 异常 / 校验失败 / 用户取消 / 流中断 / stale 会话 / 会话重置
- 轮内副作用 sink：`_life_mirror(fn, sink=…)`、`_trace_transition(…, sink=…)` 延迟到 commit
- **world 侧例外**（用户决策：用户动作即事实）：场景/时段/事件刷新保持即时

### A8 修复（施工中新发现）

`mirror_scene_first(new_scene, arc_value)` 中 `arc_value` 是未定义名 → 恒抛 `NameError` 且被 `except Exception: pass` 吞掉 → 人生账本 `scene_first` 从未落过一条（`data/life.db` 只有 `genesis` 即证据）。

### V16.2.1 修复（真机确认阶段暴露）

`TwinChatApp` 存在**两份** `_handle_command`（V16.0-mf 在文件后部又写了一份精简版），类体后定义覆盖前定义 → `/mansion` `/empire` `/late` 全部落入「未知指令」，V10.9.2 富状态面板成死代码 → 合并为唯一路由。
