# A18 收口：`_log` 双档（常规缓冲写 / 关键事件强制 fsync）

## 目标

把 `gui.py:_log` 从「每条 open+write+flush+fsync」改为**两档**：

- **常规档**（默认）：模块级**常开句柄** + `flush`（不 fsync）——覆盖 `gui.py` 内 104 处调用中的绝大多数；
- **关键档** `_log(msg, durable=True)`：`flush + fsync`——崩溃/异常/存档/取证/生命周期等**必须留证**的事件；
- `atexit` 注册「flush + close」，正常退出零丢失；`REZERO_LOG_DURABLE=1` 环境开关**一键回退**为全量 fsync（取证期/排障期用）。

## 背景（实测数据，V16.4.0 探针）

| 方案 | N=200 | 单条 |
|---|---|---|
| 现行 `open+write+flush+fsync` | 145.8 ms | **729 µs** |
| 常开句柄缓冲写 | 1.6 ms | **8 µs**（**94×**） |

风险面已核：**崩溃取证不依赖 `_log`**——`runtime/forensic/crash_dump.py` 自带预打开句柄 + flush + rename 管线（`:102/:162-166`），`_log` 丢失尾部只影响调试文本。

## 非目标

改日志格式/轮转/级别体系；动 `runtime/forensic`；动 `REZERO_GUI_LOG` 路径语义；给 `_log` 加参数以外的签名变化。

## 接口/数据是否变化

`_log(msg)` → `_log(msg, durable: bool = False)`（默认参数 ⇒ 104 处调用点零改动）；无存档/数据格式变化。

## 测试方式

1. 新用例：① 常规档**不调用** `os.fsync`（monkeypatch 计数 = 0）；② `durable=True` 恰调用 1 次；③ `REZERO_LOG_DURABLE=1` 时常规档也 fsync（回退开关有效）；④ 日志内容仍写入 `REZERO_GUI_LOG` 指定文件且可读回。
2. 计时探针（Temp/hermes-verify-*.py，跑完删）：N=200 常规档应落到 **≤ 20 µs/条**量级。
3. 全量 `pytest tests/ -q`（295）+ 隔离校验 + 冒烟 31/31。

## 回滚方式

① 环境变量 `REZERO_LOG_DURABLE=1` 即时回退（无需改代码）；② `git revert` 该提交。

## 风险

- 强杀/断电时**常规档尾部若干条日志**可能丢失 → 接受（关键事件走 durable；取证 dump 独立管线）。
- 常开句柄在多进程/被清理工具删文件时行为：句柄指向已删除文件仍可写 → 可接受（有 `REZERO_LOG_DURABLE` 与重开兜底：写入异常时重开一次）。
