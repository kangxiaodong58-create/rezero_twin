# A18 收口：`_log` 双档（常规缓冲写 / 关键事件强制 fsync）

## 目标

把 `gui.py:_log` 从「每条 open+write+flush+fsync」改为**两档**：

- **常规档**（默认）：模块级**常开句柄** + `flush`（不 fsync）——覆盖 `gui.py` 内 103 处调用中的绝大多数（buffered **50** 处）；
- **关键档** `_log(msg, durable=True)`：`flush + fsync`——**精确 53 处**（规则 E/P/L/T，逐条 `gui.py:line` 清单见 `docs/devlog/步1-4前置材料_2026-09-27.md` §1，**审计 F13-1 阻塞项已闭合**）；
- **线程安全**（审计 F13-2 结论：`VignetteWorker.run` 在 QThread 内调用 `_log` ⇒ **会跨线程**）：写入加 `threading.Lock`（临界区含 flush/fsync）；**崩溃路径不阻塞**——用 `acquire(timeout=0.5)`，超时即放弃本条（防崩溃时死锁）；
- **atexit**（审计 F13-3）：`atexit.register(_log_close)` 放**模块导入期**；`_log` 内对「句柄已关闭/None」**重开兜底**（覆盖 atexit 之后与崩溃处理器的调用）；
- `atexit` 注册「flush + close」，正常退出零丢失；`REZERO_LOG_DURABLE=1` 环境开关**一键回退**为全量 fsync（取证期/排障期用）。

## 背景（实测数据，V16.4.0 探针）

| 方案 | N=200 | 单条 |
|---|---|---|
| 现行 `open+write+flush+fsync` | 145.8 ms | **729 µs** |
| 常开句柄缓冲写 | 1.6 ms | **8 µs**（**94×**） |

风险面已核：**崩溃取证不依赖 `_log`**——`runtime/forensic/crash_dump.py` 自带预打开句柄 + flush + rename 管线（`:102/:162-166`），`_log` 丢失尾部只影响调试文本。
