### F21-6（建议）：`delta` 语义边界（显式记录，供未来审计）

| 场景 | base | candidate | 轮内主线程改 | delta | 结果 |
|---|---|---|---|---|---|
| 主线程改 A，本轮未碰 A | A_old | A_old | A_new | 无 A | **A_new 保留** ✅ |
| 主线程改 A，本轮也改 A | A_old | A_new | A_mid | 有 A = A_new | **A_new（本轮胜）** |
| 主线程未改 A，本轮改 A | A_old | A_new | — | 有 A = A_new | A_new ✅ |

⇒ 语义 = **「本轮改过的字段以本轮为准；本轮没碰的字段一律不动」**。执行时同份表落进 devlog。

# 步 8：A10 跨线程提交收口（撕裂读 + 陈旧整快照回写）

## 目标

把 `TurnTxn.commit()` 的跨线程写收口为「**加锁的原子应用 + 只写回本轮真正改动的字段**」，消除两处结构性风险：
① 撕裂读（读到 `locked=True` 配旧 `oni_stage` 这类混合态）；② 陈旧整快照回写（静默丢弃轮内别处对引擎的修改）。

## 现场事实（只读侦察，2026-09-27）

| 项 | 现状 | 位置 |
|---|---|---|
| 写入口 | `TurnTxn.commit()` → `self.engine.apply_dict(self.candidate.to_dict())`——**整快照**、**N 次逐字段赋值**（非原子） | `shared/state.py:88-100` |
| 执行线程 | commit 由 `llm/bridge.py:467` / `:586` 调用 ⇒ **LLM worker 线程** | — |
| 读入口（主线程） | `engine.snapshot()`：`gui.py:2257`（面板定时器）/ `:2947` / `:3024` / `:3045` + `bridge.py:703` | `shared/state.py:1379` |
| 锁 | **全无**（`threading` 在 `state.py` 零出现） | — |
| 候选副本机制 | M3 后真身在本轮内**不变**（`begin_turn` 造副本；面板读的是稳定真身）⇒ 撕裂窗口**只剩 commit 那一刻**；陈旧回写窗口 = 轮内主线程改引擎时 | `shared/state.py:868-880` |
| `apply_dict` 的键语义 | 绝大多数键是 `data.get(key, 当前值)` ⇒ **天然支持部分字典**；**例外**：`user_name` 是「缺键 → 置 None」⇒ **delta 会误清空用户名** | `shared/state.py:980-982` |
| 同域已修项 | `ReZeroLLMBridge._anniv_cache`（原类级字典、跨实例共享）**已在 SPEC-15/A6 实例化修复** ⇒ A10 该子项**不再成立** | — |

## 设计（选「**加锁 + 增量写回**」；三选一里的理由见下）

1. **加锁（对应候选②）**：`HardStateEngine.__init__` 增 `self._lock = threading.Lock()`。
   - 持锁方法：`apply_dict()` · `snapshot()` · `to_dict()`；
   - **整段 `apply_dict` 一次性持锁** ⇒ 读者不可能看到半套字段（撕裂读消失）；
   - 调用图显示**无嵌套持锁路径**（F21-5）⇒ 普通 `Lock` 即最小必要，注释保留「未来若出现嵌套 → 改 RLock」；
   - `snapshot()` 的 `events=` 改为 `list(self.events)`（断开唯一共享容器引用，F21-1）；
   - 锁只保护这几个入口，**不做全局串行化**（不碰 LLM 调用，锁内零 I/O、零信号发射）。
2. **增量写回（补候选②的短板，兼采③的语义）**：commit 只写「本轮真正改动过的字段」——
   - `begin_turn()` 把**已有的一次** `to_dict()` 结果一并交给 `TurnTxn`（无额外开销）；
   - **`base` 必须是 `begin_turn` 时刻的快照**（F21-3 写死；不得在 commit 时重取真身，否则主线程轮内修改会被误判覆盖）；
   - `commit()` 计算 `delta = {k: v for k, v in candidate.to_dict().items() if base.get(k) != v}` → `engine.apply_dict(delta)`；
   - 语义写死：**同一字段若轮内被别处改过、且本轮也改了它，以本轮为准**；本轮没碰的字段一律不动 ⇒ 陈旧回写不可能再发生。
3. **前置修正（必须同批做，否则 delta 不安全）**：`apply_dict` 的 `user_name` 从「缺键 → None」改为「**缺键 → 保持当前**」（显式传 `None` 仍置空）。现有调用方（存档恢复传全量字典）行为不变。
4. **为何不选候选①（QueuedConnection 回主线程 commit）**：bridge 是纯 Python 模块、须保持零 Qt 依赖；把 commit 挪到主线程需要 worker→主线程→commit→回传确认的同步往返，**引入阻塞/死锁面**，远超本项收益。理由记入本文，供审计复核。
