# 氛围行「语病 + 显示不全」修复

## §1 现状与根因（2026-09-28 实测，逐条有据）

| 现象 | 根因 | 证据 |
|---|---|---|
| **语病**：与「为客人大人哦」同行 | **存档里的 `user_name` 就是脏值**——不是模板问题 | `dist/data/memory.json` 实测 `user_name = '为客人大人哦'`；模板只是 `gui.py:3033` `ambient += f"  ·  与{state.user_name}同行"` |
| 脏值怎么来的 | `shared/state.py:_extract_name`（口语化提取，patterns 仅 4 个正则）**没有任何内容质量校验**；注释自承历史 bug：「原实现使 `_extract_name` 在 `user_name` 已设置时返回旧名」⇒ 旧版会反复拼接 | `shared/state.py:1350` 注释 + 现行 patterns（`我叫/称呼我/我的名字是/我是/请叫我` + 1–8 字） |
| 脏值改不掉 | **全仓没有用户可用的纠正入口**：写入路径只有 `state.py:800`（构造）与 `:1354`（自动提取） | `grep "user_name ="` 全仓仅这两处 |
| **显示不全** | `format_world_line(max_event=14)` 硬切，且**切点天然落在逗号后**——事件表全是「A，B」两段式，「正晒着太阳」这种最有画面感的修饰被切掉，留下「跳了进来，…」吊着逗号 | `gui.py:_refresh_ambient` 传 14；状态栏传 **16**（A15 遗留的不一致） |
| （附）该函数无测试 | `grep format_world_line tests/` 为空 | — |

## §2 目标（3 项）

1. **写入侧加质量闸**：`user_name` 不符合「像名字」的判据时**拒收**（提取器不写、显示侧降级）；并提供**用户可用的纠正入口**（脏值可自救，不必清档）。
2. **显示侧降级**：名字不可用时，「与{名字}同行」段降级为「**与你同行**」（不隐藏该段、不影响其余文案）。
3. **截断语义化**：超长事件按**子句**截——优先保留完整第一子句 + 「…」，不再出现「，…」吊逗号；并把两处调用点的长度**统一**（14/16 → 16）。

## §3 非目标

- 不改事件表内容与权重（`shared/state.py` 的 `cat_visitor` 等池子原样）；
- 不改 `_extract_name` 的正则清单（只加**质量闸**，不加新模式）；
- **不自动清洗**用户存档里的既有脏值（改档 = 数据动作，风险不对等）——由用户用新命令自己纠正；
- 不改氛围行结构（`period · weather · event · 与X同行` 四段保留）。

## §4 设计（参数表）

| 项 | 现值 | 方案 |
|---|---|---|
| 名字判据 | 无 | 新增 `shared/state.py:is_valid_user_name(name)`：非空、长度 1–8、**不以介词/连词开头**（`为和与在把被让对向从到`）、**不含语气助词**（`的了呢吧哦啊嘛呀`）。命中任一 ⇒ 判脏（「为客人大人哦」正好两头都踩） |
| 提取闸 | 无 | `_extract_name` 返回值过 `is_valid_user_name`，不过则返回 `None`（继续用「客人大人」兜底，行为与"从未设置"一致） |
| 纠正入口 | 无 | `HardStateEngine.set_user_name(name)`（含同一判据 + 写 `name_first` 人生账本条目，与既有语义一致）＋ 命令 **`/称呼 小东`**（`_handle_command` 内，成功回 transient 提示「好，以后就叫我『小东』。」；名字非法则提示不带脏值回显） |
| 显示降级 | `与{user_name}同行` | `与{user_name}同行` **if valid** else **`与你同行`** |
| 截断算法 | `ev[:14] + "…"` | `_shorten_event(ev, n)`：总长 ≤ n 原样；否则取**第一个子句**（按 `，,` 切）——子句 ≤ n 用「子句…」，子句仍超长才硬切。**保证：不出现「，…」** |
| 长度统一 | 氛围行 14 / 状态栏 16 | **两处统一 16**（氛围行 +2 字，真机看是否仍单行放得下；放不下则回 14，同批真机定） |
