## §1 缺陷（实锤）

`build.ps1` 失败/正常退出时的恢复分支：

```powershell
Copy-Item $TempBackup $DistData -Recurse -Force     # 目标已存在 ⇒ 把备份目录**嵌套**复制进去
Remove-Item $TempBackup -Recurse -Force -ErrorAction SilentlyContinue
```

当 `dist/data/` 在恢复时**已存在**（失败构建后未清干净）⇒ 备份被复制成
`dist/data/rezero_data_backup_<ts>/`，**原位反而没有** `conversations.db / life.db / memory.json`。
本次实测：数据未丢（都在子目录里），已原样恢复；但**下一次未必这么幸运**（用户看到"存档没了"）。

## §2 目标

- 恢复前**先清目标目录**（或改为「复制内容」语义：`Copy-Item "$TempBackup\*" $DistData -Recurse -Force`）；
- 恢复后**自检**：断言 `conversations.db` / `memory.json` 存在，否则 **abort + 大声报错**（不得静默继续）；
- 构建成功路径的末尾同样自检（现在的输出 `data/: exists but no conversations.db` 只是提示，不阻断）。

## §3 非目标

不改构建产物、不改 spec 文件、不动 `.env` 逻辑。

## §执行记录（2026-10-10，分支 `fix/SPEC-20260922-30-build-restore`）

### 缺陷复现（旧语义，实测）
`Copy-Item <src> <existing-dst> -Recurse` ⇒ 在 dst 下**新建 src 子目录**（与 `cp -r` 同陷阱）。实测 W 命令输出「嵌套产生: src」；正是 16:39 事故的成因。

### F30-1..5 闭环
| 审计项 | 落地 |
|---|---|
| **F30-1** abort 机制 | 恢复逻辑收敛为函数 `Restore-DistData`；自检失败 = `throw`（顶层已有 `$ErrorActionPreference="Stop"`）⇒ 立即中止；**abort 时保留备份**（`Remove-Item $BackupPath` 仅在自检**通过后**执行） |
| **F30-2** 清空 vs 复制内容 | 取**内容语义**：`Copy-Item (Join-Path $BackupPath "*") $TargetPath -Recurse -Force`——目标里多出的文件保留，**绝不因恢复丢文件** |
| **F30-3** 触发条件与路径 | 唯一实现 + 两条调用：① PyInstaller 失败分支（catch 后续）② 成功分支（Step 4）。**执行路径图**：备份（Step 1b，目标不存在 ⇒ 旧代码此处本就安全）→ 清理 build/dist（Step 2）→ 构建（Step 3）→ 失败：`Restore-DistData` + `exit 1`；成功：`Restore-DistData` + `Remove-StaleDataBackups`（Step 4）→ 部署 .env（Step 5）→ 验证 |
| **F30-4** 备份轮转 | `Remove-StaleDataBackups`：仅成功路径调用，清 `%TEMP%` 中 **>3 天**的 `rezero_data_backup_*`；失败路径备份**永不自动删** |
| **F30-5** 干跑 | 新增 `-TestRestore`：不动构建、不碰 dist，造沙箱跑两场景 |

### 施工坑（务必带走）
**PowerShell 5.1 按 ANSI 读 BOM-less 文件** ⇒ 往 `build.ps1` 注入中文注释会让部分多字节字**吞掉后续字节**（引号/换行），脚本直接语法错。
本仓该脚本**必须纯 ASCII 注入**（原文件仅 72 个非 ASCII 字节、均在字符串内）；本次实现后**非 ASCII 字节数 72→72 不变**（脚本自带断言）。
