# SPEC-20260922-30：`build.ps1` 数据恢复逻辑加固（L1，数据安全）

- **SPEC-ID**：SPEC-20260922-30
- **级别**：L1（构建脚本修复；**数据安全相关**）
- **来源**：SPEC-28 施工中实测事故（2026-10-10 16:39 失败构建）
- **等待批准**：**是**

## §1 缺陷（实锤）

`build.ps1` 失败/正常退出时的恢复分支：

```powershell
Copy-Item $TempBackup $DistData -Recurse -Force     # 目标已存在 ⇒ 把备份目录**嵌套**复制进去
Remove-Item $TempBackup -Recurse -Force -ErrorAction SilentlyContinue
```

当 `dist/data/` 在恢复时**已存在**（失败构建后未清干净）⇒ 备份被复制成
`dist/data/rezero_data_backup_<ts>/`，**原位反而没有** `conversations.db / life.db / memory.json`。
本次实测：数据未丢（都在子目录里），已原样恢复；但**下一次未必这么幸运**（用户看到"存档没了"）。

## §2 目标

- 恢复前**先清目标目录**（或改为「复制内容」语义：`Copy-Item "$TempBackup\*" $DistData -Recurse -Force`）；
- 恢复后**自检**：断言 `conversations.db` / `memory.json` 存在，否则 **abort + 大声报错**（不得静默继续）；
- 构建成功路径的末尾同样自检（现在的输出 `data/: exists but no conversations.db` 只是提示，不阻断）。

## §3 非目标

不改构建产物、不改 spec 文件、不动 `.env` 逻辑。

## §4 需要读取/修改的文件

@build.ps1（恢复分支 + 自检）

- 一次完整构建 + 启动复核（日志正常 + 存档可读）。
