# CI 首跑修红：失败取证可观测化 + Qt 夹具平台可移植化

## 目标

批量搬运后 **CI 首跑 `35800087797` 红**（步骤 7「全量测试 + 数据隔离校验」失败，步骤 6 结构守卫通过）。本 SPEC 做两件事：

1. **让失败原因公开可读**：GitHub Actions 原始日志需登录（实测 `GET …/actions/runs/<id>/logs` → **403**，无 token；artifacts 为 0），而 **check-run annotations 端点无需登录即可读**（实测：该 run 的 annotations 可读，含 `Process completed with exit code 1.`）。因此把失败摘要转成 annotations 输出 → 无凭证也能定位，且永久提升 CI 可审计性。
2. **修掉最可疑的平台专有写法**：`tests/test_motion.py` 三处 `monkeypatch.setenv("QT_QPA_PLATFORM", "windows")`（为让 `motion.enabled()` 为真——`motion.py:25` 规定 offscreen 恒禁用）。当 QApplication **尚未创建**时把平台改成 `windows`，Linux runner 会去加载不存在的平台插件 → Qt 致命错误。改为：**session 级夹具在改环境变量之前先固化 QApplication**（`conftest.py` 新增 `qapp`），夹具顺序由 pytest 的 scope 规则保证（session 先于 function）——**不改变任何测试意图与断言**。

## 非目标
