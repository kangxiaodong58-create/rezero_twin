## §11 追加（同日真机追加反馈：「历史定位时**聊天输入框**也边框闪光」）

### 第二个机制（与 §2 F1 **不同源**，互相独立）
`ui/mixins/shell_setup.py::eventFilter` 在 **FocusIn/FocusOut** 上**程序化**换样式：

```python
if source is self.input_box and event.type() == QEvent.FocusIn:
    self.input_box.setStyleSheet(theme.input_box_highlight())   # 2px accent 金边
if source is self.input_box and event.type() == QEvent.FocusOut:
    self.input_box.setStyleSheet(theme.input_box_normal())      # 1px 淡边
```

- **历史渊源**：V14.4（Trial #1 B-02）「输入框聚焦高亮——小白首启区分输入框与搜索框」；
- **为什么 §2 F1 没覆盖**：F1 删的是 QSS 里的 `:focus` **伪状态规则**，这里是**代码在事件里主动 setStyleSheet**——两条独立路径；
- **为什么用户会在"定位"时看到**：`history.py:62/100` 定位/关浮层后会 `input_box.setFocus()` ⇒ 触发 FocusIn ⇒ 金边出现，视觉上就是「定位时输入框边框闪光」。

### 修法
1. 移除 eventFilter 的两个换样式分支（保留 Enter 发送的 KeyPress 分支 + 樱花层 Resize 分支）；
2. 删除 `theme.input_box_highlight()` / `theme.input_box_normal()`（唯一调用点已移除，死代码）及 `__all__` 条目；
   输入框外观统一由 `theme.input_box()` 单一来源负责（顺带消除"聚焦过一次后永久多一条 1px 边"的潜在不一致）。

### 证据（像素级 + 用例级）
- **定点像素探针**：定位后 / 显式聚焦后 / 失焦后 —— 输入框与其外框**像素完全一致**，`styleSheet` 未变；
- 新增用例 `test_input_focus_does_not_restyle`（直接打在 `eventFilter` 上，比"QSS 无 :focus"更贴根因）；
- 全量 **386 passed** · golden 重采 · 基线 8/8 一致 · 冒烟 31/31 · 隔离 ✓。

### 教训（追加到 §9）
**「聚焦高亮」在本仓有两条实现路径**：① QSS `:focus` 伪状态；② 事件过滤器里 `setStyleSheet`。
查这类"某状态变色"的问题，**两条都要查**——只查 CSS 会漏掉事件驱动的那条。
