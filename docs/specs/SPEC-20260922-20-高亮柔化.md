# SPEC-20：搜索命中高亮柔化（两表面分档）

## 目标

把命中词的**不透明亮黄底 + 硬黑字**改为**半透明暖黄底 + 下划线**，并按**两个显示表面**分档：
聊天区是**浅底气泡**、历史浮层是**深底卡片**——同一套黄底在浅底上刺眼、在深底上更刺眼，需分别取值。

## 现场事实（只读侦察，2026-09-27）

| 项 | 现状 |
|---|---|
| token | `design_tokens.py:53` → `"search_hit": "#FFEB3B"`（单一值，两个表面共用） |
| span 样式 | `gui.py:267` → `background-color: {COLORS['search_hit']}; color: #1a1a1a;`（不透明底 + 强制近黑字） |
| 调用点 ①（深底） | `gui.py:1357`（`HistoryItemWidget` 正文）+ `:1397`（摘要行）——卡片底色 `bg_surface_2` 为**深色** |
| 调用点 ②（浅底） | `gui.py:2475`（`highlight_hits` → 聊天区气泡，浅色气泡） |
| 现有测试 | `tests/test_ui_offscreen.py::test_search_highlight_v141` 只断言**结构**（`<span` 数量 / 转义 / clear 往返），**未断言样式字符串** → 改样式不破坏现有断言 ✓ |
| 消费者盘点 | `COLORS['search_hit']` 全仓**仅** `gui.py:267` 一处；`tests/**` 零引用 → 可安全替换（`_search_hit_text` 是属性名，与 token 无关） |

## 设计（取值写死，不留实现自由发挥）

1. **token 改为一组两档**（`design_tokens.py`）：

   ```python
   SEARCH_HIT = {
       "light": {"bg": "rgba(255, 205, 96, 0.42)", "fg": ""},          # 聊天区浅底气泡
       "dark":  {"bg": "rgba(255, 200, 80, 0.22)", "fg": "#FFE6B0"},  # 历史浮层深底卡片
   }
   ```

   并**删除**旧 `COLORS["search_hit"]`（唯一消费者随之改写，见上表）。

2. **`highlight_plain_text(text, keyword, surface="light")`**（新增可选参数，默认值保持浅底路径行为；不改函数契约的调用方式）：
   - `light`：`background-color: <bg>; text-decoration: underline;` —— **不再强制文字色**（保留气泡原色，这是「生硬」的主因之一）；
   - `dark`：`background-color: <bg>; color: <fg>; text-decoration: underline;` —— 深底需要提亮文字才有对比；
   - 未知 surface 值 → 回退 `light`（不抛异常）。
   - 调用点：`:1357` / `:1397` 传 `surface="dark"`；`:2475` 保持默认。
3. **兼容性口径（rgba 在 Qt 富文本）**：首选 `rgba(r,g,b,a)`（语义无歧义）。执行时先跑**离屏渲染探针**验证半透明确实生效（渲染 → 取 span 内像素 → 与「纯文字色」对照，若被忽略/渲染为不透明立即发现）；若不生效，退化为**按底预乘出的不透明色**并在 SPEC 附录记录实测结论。
